.Entity and Workflow sharding
****
Akka spreads the instances of xref:reference:glossary.adoc#stateful_component[stateful components] across the nodes of the service and keeps exactly one instance for each xref:reference:glossary.adoc#id[ID] in the cluster. The xref:reference:glossary.adoc#component_client[component client] routes each call to the node that hosts the instance, which handles its messages one at a time, so you have no concurrency to manage. Active instances keep their state in memory; idle ones are passivated and recovered from durable storage when used again. See xref:concepts:runtime.adoc#_sharding_and_single_ownership[Sharding and single ownership] and xref:concepts:runtime.adoc#_passivation_and_recovery[Passivation and recovery].
