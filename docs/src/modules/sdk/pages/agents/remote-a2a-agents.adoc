= Remote A2A agents
:page-component-type: agent
:page-summary: A remote A2A agent is an agent in another system that your service calls over the Agent2Agent (A2A) protocol, with credentials and TLS settings that you configure by name.
:page-when-to-use: Calling an agent that another team or vendor runs, and that publishes an Agent Card.
:page-related: sdk:agents/extending.adoc, sdk:mcp-endpoints.adoc, sdk:setup-and-dependency-injection.adoc
:page-prerequisites: An Akka project and the URL of the remote agent's Agent Card.
:page-persona: builder-developer, builder-ai-ml

A remote A2A agent is an agent that runs outside your service and speaks the Agent2Agent (A2A) protocol. The remote agent publishes an Agent Card, which is a JSON document that names the agent, lists its skills, and says how to reach it. A skill is one task that the agent can do. Your service calls the agent with `A2aClient`, which reads the Agent Card, sends the requests, and applies the credentials and TLS settings that you configure for that agent.

This page describes how an agent offers the skills of a remote agent to its model as tools, how to name a remote agent in configuration, how to give your service credentials for it, how to set the certificates that TLS uses to reach it, and how to choose the skills and the timeout of the tools.

[#remote-agents-as-tools]
== Remote A2A agents as tools

An agent can offer the skills of a remote A2A agent to its model as tools. Pass one or more `RemoteA2aAgent` instances to `a2aAgents` in the effect of the agent, as you pass remote MCP servers to `mcpTools`.

----

----
<1> `a2aAgents` takes one or more remote agents.
<2> `RemoteA2aAgent.named` takes a name configured under `akka.javasdk.a2a.remote-agents`. The tool calls use the credentials and TLS settings of that configuration. See <<naming-remote-agents>>.
<3> `RemoteA2aAgent.fromCard` takes the URL of an Agent Card. The tool calls use no credentials and no custom TLS settings.

When the agent handles a request, it reads the Agent Card of each remote agent. The client caches the card, as <<naming-remote-agents>> describes. The agent offers each skill on the card to the model as one tool:

* The name of the tool is the name of the remote agent and the id of the skill, joined by `_`, for example `claims_claim-status`. For a remote agent from `fromCard`, the name is the `name` on its Agent Card. Characters that model providers do not accept in tool names become `_`. A name longer than 64 characters is shortened and ends with a hash of the full name.
* The description of the tool is the description of the skill, followed by the names of the skill and of the remote agent.
* The tool takes a required `message` string and an optional `data` object. The agent sends the message as a text part and the data as a data part.

When the model calls the tool, the agent sends the message to the skill with `SendMessage`. The agent uses its session id as the A2A context id, so the remote agent can keep one conversation for each session. The agent returns the reply to the model as text:

* A message returns its text parts. A data part becomes its JSON text. A file part becomes a line with its file name and media type, and its URL when it has one.
* A completed A2A task returns the parts of its artifacts and of its status message.
* An A2A task that failed, was rejected or was canceled returns a text that starts with `Error:` and names the state.
* An A2A task that has not finished, such as a submitted or working task, or a task that needs input, returns the id and the state of the task. The agent does not wait for the task to finish.

The agent stores the tool call and its result in session memory and records them in the interaction log, as for any tool.

A failed call does not fail the agent request. When the remote agent answers with an error, does not answer within the timeout, or cannot be reached, the model receives a text that starts with `Error:` and describes the failure. The model can then try again or answer without the remote agent. A tool call without a message gets the same kind of text. The result does not carry the error flag that an MCP tool error carries.

The agent request fails before the model is called in two cases:

* The Agent Card of a remote agent cannot be read.
* The name of a tool is the same as the name of a function tool of the agent, or of another skill. The request fails with `IllegalArgumentException`. Use `withAllowedSkills` to leave out a skill whose name clashes. See <<skills-and-timeouts>>.

A `ToolCallGuardrail` can allow or deny each call. See xref:sdk:agents/guardrails.adoc#_implementing_a_tool_call_guardrail[Implementing a tool call guardrail].

<1> `A2aClient` is injected into the constructor.
<2> `forAgent("claims")` reads the settings of `akka.javasdk.a2a.remote-agents.claims`. It throws `IllegalArgumentException` when the name is not configured or its settings are not valid.
<3> `send` takes the id of a skill and a message. A2A has no field for the skill, so the client sends the id as `skillId` in the metadata of the request. Call `inContext` on the result to continue a conversation with a context id.

For a one-off call, pass the URL of an Agent Card to `forAgent` instead of a name. An agent that you give by URL has no credentials and no custom TLS settings, and takes its timeouts from `akka.javasdk.a2a.defaults`. For this reason, the `defaults` cannot hold credentials: the service fails to start when `akka.javasdk.a2a.defaults.auth.type` is not `none`.

The settings of a remote agent are:

[cols="2,1,4",options="header"]
|===
| Setting | Default | Meaning

| `card-url`
|
| The URL of the Agent Card. It must start with `http://` or `https://`.

| `timeout`
| `60s`
| The longest time to wait for the agent to answer a request. For a streamed response, the limit applies to the start of the response.

| `card-refresh`
| `10m`
| How long the client uses a cached Agent Card before it fetches the card again.

| `auth`
| `type = none`
| Credentials. See <<credentials>>.

| `ca-bundle`, `client-certificate`, `client-key`
|
| TLS settings. See <<tls>>.
|===

The client reads the Agent Card on the first call and caches it. It then chooses a protocol binding from the interfaces that the card lists. The client uses the JSON-RPC binding when the card lists it, and the HTTP+JSON binding otherwise. When the card lists neither binding, every call fails with `A2aClientException`.

Each request carries an `X-Akka-Caller` header that identifies the calling component, and the `A2A-Version` header. A call that runs inside a traced request also carries the trace headers.

A call fails with one of two exceptions:

* `A2aRemoteErrorException` means that the remote agent answered with a protocol error. Its `code()` is the JSON-RPC error code, for example `-32001` for a task that does not exist. Its `reason()` is the A2A reason, for example `TASK_NOT_FOUND`.
* `A2aClientException` covers every other failure, such as an unreachable agent, a timeout, a rejected credential, a failed TLS handshake, or a reply that is not valid A2A. `A2aRemoteErrorException` is a subclass of `A2aClientException`.

[#credentials]
== Credentials for remote agents

The `auth` setting of a remote agent chooses how the service proves its identity. The client sends the credentials on every request to the agent, including the request for the Agent Card.

The client sends credentials only to `https://` URLs, and to `http://` URLs on `localhost` for local development and tests. `forAgent` throws `IllegalArgumentException` when the `card-url` or the `token-url` of an agent with credentials is another `http://` URL. A call fails with `A2aClientException` when the Agent Card lists an interface at such a URL.

Take secret values from environment variables with an optional substitution, such as `${?POLICIES_API_KEY}`. Do not write secrets in `application.conf`. To supply the variables to a deployed service, see xref:operations:projects/secrets.adoc[]. An optional substitution for a variable that is not set leaves the setting out. When the setting is required, such as `client-secret`, `forAgent` throws `IllegalArgumentException` with a message that names the missing setting.

=== OAuth 2.0 client credentials

With `type = oauth2-client-credentials`, the client gets an access token from the token endpoint and sends it as a bearer token. The `scope` setting is optional.

----

----

The client requests a token with a form post of `grant_type=client_credentials` and, when you set it, the `scope`. By default, the client sends the `client-id` and the `client-secret` in an HTTP Basic `Authorization` header (`client_secret_basic`). For a token endpoint that expects them in the form instead, set `token-endpoint-auth-method = "client_secret_post"`. It reuses the token until 30 seconds before the token expires. When the token lives for less than one minute, the client refreshes after half of its lifetime. When the token endpoint does not give a lifetime, the client assumes five minutes. Calls that start at the same time share one token request.

When the remote agent answers a request with status 401, the client discards the token, requests a new one, and sends the request again once. A second 401 fails the call.

[#tls]
== TLS and client certificates for remote agents

A remote agent at an `https://` URL is reached over TLS. By default, the client verifies the certificate of the agent against the certificates that the Java runtime trusts, and checks that the host name of the URL matches the certificate. The settings below change this for one agent. They apply to the Agent Card and to the calls.

.{sample-base-url}/doc-snippets/src/main/resources/application.conf[application.conf]
----
include::example$doc-snippets/src/main/resources/application.conf[tag=a2a-remote-agent-tls]
----

`ca-bundle`:: One or more PEM certificates of the authorities that signed the certificate of the agent. The bundle replaces the certificates that the Java runtime trusts for this agent. Use it when the agent has a certificate from a private authority.

`client-certificate` and `client-key`:: The certificate chain and the private key that the service presents when the agent requires mutual TLS. Put the certificate of the service first, followed by any intermediate certificates. Set both settings or neither.

Each of the three settings holds either PEM text or the path of a file that holds PEM text. A value that contains `-----BEGIN` is read as PEM text. Any other value is read as a path. Passing the PEM text in an environment variable avoids a file in the container image.

The token endpoint of OAuth 2.0 client credentials has its own TLS settings, because it is usually another server than the agent. By default, the client verifies the token endpoint against the certificates that the Java runtime trusts and presents no client certificate. For an identity provider with a certificate from a private authority, or one that requires mutual TLS, set `auth.token-ca-bundle`, `auth.token-client-certificate` and `auth.token-client-key`. They take the same values as the settings above.

The private key must be an unencrypted PKCS#8 key, which starts with `-----BEGIN PRIVATE KEY-----`. The key can be an RSA, EC or Ed25519 key. `forAgent` throws `IllegalArgumentException` for a key in another format. The `openssl pkcs8 -topk8 -nocrypt` command converts a PKCS#1 or SEC1 key.

A TLS failure, such as an untrusted certificate, a certificate for another host name, or a missing client certificate, fails the call with `A2aClientException`. The message of the exception names the cause that the TLS layer reported.

[#skills-and-timeouts]
== Choosing skills and timeouts

By default, the agent offers every skill on the Agent Card to the model. Each tool adds to the request that the model reads, and a remote agent can have skills that your agent must not use. `withAllowedSkills` offers only the skills with the given ids. The model cannot call a skill that the agent does not offer. When the set names a skill that the Agent Card does not list, the agent logs a warning.

`withTimeout` limits how long a tool call waits for the reply of the remote agent. It replaces the `timeout` of the configuration for the requests of this agent, including the request for the Agent Card. When the time passes, the model receives a text that starts with `Error:`.
