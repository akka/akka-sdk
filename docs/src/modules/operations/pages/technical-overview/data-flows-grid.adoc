8+h| Akka Optimize: AI gateway

| End users and third-party agents | Inference call from outside the region (third-party agent or end user) | Prompts, messages, tool definitions, completions (streamed), embedding input | External client | Route hostname, then Contour, then agentgateway | [.conn-public]#Public# to the region ingress (Contour Envoy, TLS), then private with mesh mTLS inside (gateway port 80) | TLS at ingress (optional client certificate, optional JWT validation on the route). Mandatory Bearer API key at the gateway. | Request parameters are allowlisted per API. `+guided_*+` and `+model_revision+` are rejected. Status: In code; not yet deployed on Azure.
| Deployed Akka services | Inference call from an Akka agent in the same project | Prompts and completions | Your service pod | `+http://<endpoint>.<project>.svc.cluster.local/v1+`, routed to agentgateway | [.conn-private]#Private# (in-cluster service name, mesh mTLS) | Bearer API key | In-cluster access needs a change to the gateway network policy. Until then, Akka agents call the endpoint through its route, as in the first flow of this group. Status: Not yet supported; to confirm.
| Akka Region (AI gateway) | Gateway dispatches to the model engine | Request and response bodies | agentgateway | vLLM engine, port 8000 | [.conn-private]#Private# (pod to pod, mesh mTLS) | Linkerd mesh policy admits only the gateway's mesh identity on port 8000 | The Kubernetes network policy admits the gateway and monitoring pods. The mesh policy, not the network policy, blocks other pods in the same namespace. Status: In code; not yet deployed on Azure.
| Akka Region (AI gateway) | Gateway configuration | API keys, routing tables | agentgateway controller | agentgateway proxies | [.conn-private]#Private# (xDS over TLS) | Kubernetes RBAC | API keys are stored as Kubernetes Secrets in the project. Status: In code; not yet deployed on Azure.
| Akka Region | Usage metering | vLLM metrics labelled with model, billing ID, accelerator type and memory. No prompts or completions. | Prometheus | Engine `+/metrics+` | [.conn-private]#Private# (in-cluster scrape), then the existing region observability path | Network policy | Covers in-region serving only. Spend on external providers is metered from captured traffic. Status: To confirm.

Status: To confirm.
| Deployed Akka services (Optimize) | Capture of routed traffic for training and evaluation | Captured LLM requests and responses | gateway-router, capture-refinery | Project storage account (`captured/`, `normalized/`) | Azure Storage endpoint. Status: To confirm.
| Deployed Akka services (Optimize) | Optimize services look up the caller's project roles | Caller's Akka access token (forwarded), project ID | optimize, optimize-training, optimize-registry, portfolio, gateway-router, offline-evaluation | Akka management API | [.conn-public]#Public# (HTTPS egress from the project namespace) | Caller's Akka access token. 8+h| Akka Optimize: model serving and GPUs

| Developers | Declare models, endpoints, and GPU allocations | Model spec (Hugging Face repo and SHA, secret names, engine arguments), endpoint spec, allocation | Developer (CLI) | Region Kubernetes API, through the existing Akka control channel | [.conn-private]#Private# (peering), as for deploying a service | Akka RBAC: `+project.models.*+`, `+project.modelEndpoints.*+`. Inference must be enabled for the organization or the project. | Platform-owned vLLM flags (`--api-key`, `--trust-remote-code`, `--download-dir`, `--host`, `--tokenizer`, `--chat-template`) are refused. Status: In code; not yet deployed on Azure.
| Federation Plane / Akka Region | Sync accelerator pools and entitlement | Pool definitions (driver, product, memory, tolerations), `inference_enabled` | Federation Plane | Region | [.conn-public]#Public# (outbound TLS tunnel from the region, through the Teleport agent) | Teleport mutual TLS certificates | No new connection. Uses the existing Teleport tunnel. Status: In code; not yet deployed on Azure.
| Akka Region (model serving) | vLLM downloads base model weights at start | Model weights, config, tokenizer | vLLM engine pod | huggingface.co | [.conn-public]#Public# (HTTPS egress) | Hugging Face token from a project secret (environment variable) | Pinned to a commit SHA. Cached on a PVC if configured. Status: In code; not yet deployed on Azure.
| Akka Region (model serving) | Fetch LoRA adapters | Adapter weights | Init container | huggingface.co (pinned SHA) | [.conn-public]#Public# (HTTPS egress) | Hugging Face token | Object-storage adapters are S3 only and not available on Azure. Status: In code; not yet deployed on Azure.
| Akka Region (model serving) | GPU binding | None (device allocation) | Kubernetes scheduler | GPU node | DRA ResourceClaim | Claim belongs to one project namespace | Models in one project that share a device index share one GPU by time-slicing. Each engine limits its own GPU memory use through vLLM configuration. Status: In code; not yet deployed on Azure.
| Akka Region | Image pulls | vLLM, agentgateway, training runtime, Optimize service, and OpenTelemetry Collector images | Kubelet | Akka image registry, or your mirror | Node egress. [.conn-public]#Public#, or [.conn-private]#private# to the mirror | Registry pull secret | Images in Akka's private registry need Akka-issued pull credentials for your mirror. The OpenTelemetry Collector image comes from Docker Hub. Status: In code; not yet deployed on Azure.
| Akka Region (model serving) | vLLM usage statistics | Anonymous usage data (hardware, model architecture) | vLLM engine pod | vLLM usage statistics endpoint | [.conn-public]#Public# (HTTPS egress) | None | vLLM sends usage statistics by default. Whether Akka disables it is to confirm. Status: To confirm.
