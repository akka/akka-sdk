= Project role bindings
:page-summary: A project role binding grants a built-in project role to a user, group or service in one project.
:page-when-to-use: When you give users or services access to a single project.
:page-related: operations:security/index.adoc, operations:security/organization-role-bindings.adoc, operations:security/custom-roles.adoc
:page-persona: operator-platform, builder-developer

include::ROOT:partial$include.adoc[]

A project role binding grants a built-in project role in one project to a principal. The project roles are `admin`, `developer`, `viewer` and `backoffice`. The xref:reference:rbac/roles.adoc[Roles] reference lists their permissions.

Project role bindings only accept built-in roles. To grant a xref:operations:security/custom-roles.adoc[custom role] on a project, create an xref:operations:security/organization-role-bindings.adoc[organization role binding] to a custom role that lists the project.

[cols="1,3"]
|===
| Role | Purpose

| `admin`
| Full control of the project, including deleting it and managing its access.

| `developer`
| Deploy and configure services, routes, secrets and other resources, without managing access or deleting the project.

| `viewer`
| Read-only access to the project, its services and routes. Secrets can not be viewed.

| `backoffice`
| Discover services and proxy requests to them, for operational support. This includes viewing entity event logs and values, and invoking methods on services that are not exposed to the internet.
|===

Organization membership is separate. See xref:operations:security/organization-role-bindings.adoc[].

[NOTE]
====
The Akka CLI can keep a project as context, so you do not need to pass the `--project` flag.

[source,command window]
----
akka config set project <project name>
----
====

== List role bindings

[source,command window]
----
akka roles list-bindings
----

Example output:
[source]
----
ROLE BINDING ID                        ROLE        PRINCIPAL                                MFA
f3e1ad17-d7be-4432-9ab6-edd475c3aa44   admin       John Smith <john.smith@example.com>      true
311e3752-30f9-43f4-99ef-6cbb4c5f14f3   developer   Jane Citizen <jane.citizen@example.com>  true
----

== Grant a role

You can invite a user by email, or add a role binding directly.

=== Invite a user by email

[source,command window]
----
akka roles invitations invite-user <email address> --role <role>
----

The user receives an email to join the project. When the user accepts, Akka creates the role binding.

=== Add a role binding directly

If the user is already a member of the project, or the project belongs to an organization and the user belongs to that organization, you can add the role binding without an invitation.

By email:

[source,command window]
----
akka roles add-binding --email <email address> --role <role>
----

By username:

[source,command window]
----
akka roles add-binding --username <username> --role <role>
----

A group from your OpenID Connect provider:

[source,command window]
----
akka roles add-binding --group <group name> --role <role>
----

See xref:operations:security/oidc-setup.adoc#assigning_project_level_roles[OpenID Connect setup].

An Akka service, using workload identity:

[source,command window]
----
akka roles add-binding --service <service name> --role <role>
----

For the walkthrough, including how to configure the service to authenticate, see xref:operations:services/workload-identity.adoc#authenticating-with-the-akka-platform-api[Authenticating with the Akka platform API].

== Delete a role binding

List the role bindings to get the role binding ID, then pass it to the delete command.

[source,command window]
----
akka roles delete-binding <role binding id>
----

== Manage invitations

List outstanding invitations:

[source,command window]
----
akka roles invitations list
----

Example output:
[source]
----
EMAIL                      ROLE
jane.citizen@example.com   admin
----

Invitations expire after 7 days. You can delete an invitation:

[source,command window]
----
akka roles invitations delete <email address>
----

To resend an invitation, delete the previous one and invite the user again.
