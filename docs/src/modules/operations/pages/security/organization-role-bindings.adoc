= Organization role bindings
:page-summary: An organization role binding grants a built-in organization role or a custom role to a user, group, service or workload identity in an organization.
:page-when-to-use: When you add users to an organization, give them organization roles, or grant a custom role.
:page-related: operations:security/index.adoc, operations:security/custom-roles.adoc, operations:security/project-role-bindings.adoc
:page-persona: operator-platform

include::ROOT:partial$include.adoc[]

An organization role binding grants a role in an organization to a principal. The role is one of the built-in organization roles (`superuser`, `project-admin`, `billing-admin` or `member`) or a xref:operations:security/custom-roles.adoc[custom role] of the organization. The principal is a user, a group, an Akka service or a workload identity.

To grant access to a single project with a built-in project role, see xref:operations:security/project-role-bindings.adoc[]. For an overview of both kinds of role binding, see xref:operations:security/index.adoc[].

The xref:reference:rbac/roles.adoc[Roles] reference lists the permissions of the built-in roles.

== List role bindings

[source,command window]
----
akka organizations role-bindings list --organization <organization name>
----

Example output:
[source]
----
ROLE BINDING ID                        ROLE                USERNAME       EMAIL                      NAME
fd21044c-b973-4220-8f65-0f7d317bb23b   superuser           jane.citizen   jane.citizen@example.com   Jane Citizen
120b75b6-6b53-4ebb-b23b-2272be974966   member              john.smith     john.smith@example.com     John Smith
7c0b6a51-1d2e-4f43-8e0c-6a1a4f3c9d10   deployer (custom)   sam.jones      sam.jones@example.com      Sam Jones
----

Custom roles show with the suffix `(custom)`.

The list shows all principals, including groups, services and workload identities, not only users. To see users who have not yet accepted an invitation, see <<manage-invitations>>.

== Grant a built-in role

You can invite a user by email, or add a role binding directly.

=== Invite a user by email

[source,command window]
----
akka organizations invitations create --organization <organization name> \
  --email <email address> --role <role>
----

The user receives an email to join the organization. When the user accepts, Akka creates the role binding.

=== Add a role binding directly

If the user is already a member, or you want to bind another kind of principal, add the role binding directly. Specify exactly one principal.

By email:

[source,command window]
----
akka organizations role-bindings add --organization <organization name> \
  --email <email address> --role <role>
----

By username:

[source,command window]
----
akka organizations role-bindings add --organization <organization name> \
  --username <username> --role <role>
----

A group from your OpenID Connect provider:

[source,command window]
----
akka organizations role-bindings add --organization <organization name> \
  --group <group name> --role <role>
----

If the organization that owns the group is not the organization you bind in, add `--group-org <organization name or id>`. See xref:operations:security/oidc-setup.adoc#assigning_organization_level_roles[OpenID Connect setup].

An Akka service, using workload identity:

[source,command window]
----
akka organizations role-bindings add --organization <organization name> \
  --service <service name> --role <role>
----

For the walkthrough, including how to configure the service to authenticate, see xref:operations:services/workload-identity.adoc#authenticating-with-the-akka-platform-api[Authenticating with the Akka platform API].

The `--role` value is the id of a built-in organization role, for example `superuser`.

[#bind-a-custom-role]
== Bind a custom role

To grant a xref:operations:security/custom-roles.adoc[custom role], use `--custom-role` with the id of the role instead of `--role`. Specify exactly one of `--role` and `--custom-role`.

[source,command window]
----
akka organizations role-bindings add --organization <organization name> \
  --email <email address> --custom-role <custom role id>
----

All the principal options above work with `--custom-role`.

Changes to custom roles and their role bindings are eventually consistent, so a new binding can take some time to take effect.

== Delete a role binding

List the role bindings to get the role binding ID, then delete it.

[source,command window]
----
akka organizations role-bindings delete --organization <organization name> \
  --id <role binding id>
----

[#manage-invitations]
== Manage invitations

List outstanding invitations:

[source,command window]
----
akka organizations invitations list --organization <organization name>
----

Example output:
[source]
----
EMAIL                      ROLE
jane.citizen@example.com   member
----

Invitations expire after 7 days. You can cancel an invitation:

[source,command window]
----
akka organizations invitations cancel --organization <organization name> \
  --email <email address>
----

To resend an invitation, cancel the previous one and create it again.

== Command names

Earlier versions of the CLI named this command group `akka organizations users`, with the commands `add-binding`, `delete-binding` and `list-bindings`. The old names still work as aliases.
