A project runs in one or more regions. Projects in Akka can span regions, with data replicated automatically between all the regions of the project. The regions can be separate cloud or geographic regions, or separate logical regions within the same cloud or geographic region. This gives you control over failure domains, the fault boundaries of your applications.

== What zones give you by default

A region is a geographic area. Each region has several availability zones, and each zone is a physically separate data center. A production environment runs across zones in one region, so it recovers from the loss of one data center with no action from you. For many workloads, zones in one region are enough.

== When you need more than one region

Add regions to a project when you need one of these:

* Recovery from the loss of a whole region, by moving traffic to another region that already holds your data.
* Serving requests from regions close to your users.
* Geographic redundancy that your compliance requirements or contracts demand.

More regions add infrastructure cost and cross-region latency, and your application must tolerate a short delay before a write in one region is visible in the others. You do not have to decide when you create the project: you can start in one region and add regions later.

For how Akka replicates the state of each component between regions, see xref:concepts:multi-region.adoc[].
