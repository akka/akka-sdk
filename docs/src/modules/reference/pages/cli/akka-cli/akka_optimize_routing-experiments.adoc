= akka optimize routing-experiments

Run a canary as a record of steps, limits and who did what

== Synopsis

An experiment owns one canary rule or one use case canary and changes traffic only by writing it.
A person takes every action, except that a crossed limit can hold or roll back the experiment, as its onCrossed says.
While the experiment runs or is held, a hand edit of its rule or canary is refused.

Write a draft with apply, then start, advance, hold, resume, roll-back, promote or release it.
check reads where the limits stand.
The router also checks a running experiment on a schedule, hourly by default, and keeps a check that judges a new hour or fails.
When a kept check finds a limit crossed, onCrossed decides: notify changes nothing, hold holds the experiment, and roll-back rolls it back.
get prints the last check kept and what the limits did.
