= akka optimize training snapshots pin

Retain a snapshot against the catalog's retention limits

== Synopsis

Retain a snapshot so that the catalog does not sweep it.

A snapshot is swept under the run's keep counts unless a holder retains it.
The two holds the service takes on its own both end with the work that took them: a running branch retains the artifact it reads until the run reaches a terminal phase, and a candidate registration retains the weights while it copies them, releasing them once the copy is durable.
Pin a checkpoint you intend to branch from or register later, while it is still available.

Both artifact kinds are pinned unless --kind specifies one, and both are pinned or neither is: a kind the catalog has already begun deleting cannot be pinned, and the request is refused rather than pinning the other kind behind it.
Pinning an already pinned snapshot has no effect.

"training runs snapshots" reports a pinned snapshot as held by retention.
Release the pin with "training snapshots unpin".

----
akka optimize training snapshots pin SNAPSHOT [flags]
----

== Examples

----
  # Retain a checkpoint to continue from later
  akka-optimize training snapshots pin 3f2a9c71bd04

  # Retain only its full training state
  akka-optimize training snapshots pin 3f2a9c71bd04 --kind trainingState
----

== Options

----
  -h, --help          help for pin
      --kind string   Artifact kind to act on, either weights or trainingState. Both kinds are covered by default
----
