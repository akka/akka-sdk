= akka optimize use-cases freeze

Fix the working set as a manifest

== Synopsis

A freeze snapshots the working set and discards the below-threshold bucket.

Every use-case must carry a label and a backend: a routing decision has to be traceable to the whole set of data it was made on, so a backend cannot be changed afterwards -- changing one means another freeze under another tag.

Backend ids are not validated here or by the service.
They are owned out of band by whoever operates the gateway.

Freezing does not route anything.
Deploy the manifest to make it live.

----
akka optimize use-cases freeze --as TAG --backend LABEL=BACKEND [flags]
----

== Options

----
      --as string             the tag to bind this manifest to (required, and bound once)
      --backend stringArray   LABEL=BACKEND, repeatable; one for every labelled use-case
  -h, --help                  help for freeze
----
