= akka optimize training endpoints info

Show what an endpoint here can serve

== Synopsis

Show what an endpoint of this deployment can serve and what one claims.

"Adapter ranks" is the largest LoRA rank an endpoint loads.
An adapter of a lower rank loads too, and a run that trains above it is refused at submission.
"Adapters loaded" is how many adapters one endpoint has loaded at once beside its base model.
More can attach, and one is loaded when a request first names it.
"GPUs per endpoint" and the device type are what one endpoint claims for as long as it answers.
The deployment sets each of these, and "training endpoints create" takes none of them.
The JSON output also lists the rank limits the serving engine accepts, which an operator chooses the deployment's limit from.

On the vLLM engine, each architecture of a selected base model is listed with what an endpoint returns for a model of it beside its text: tool calls, where the architecture has a tool-call parser, and reasoning apart from the answer, where it has a reasoning parser.

An endpoint serves a base model and adapters over it.
A model registered as whole weights is not served.

[source,shell]
----
akka optimize training endpoints info [flags]
----

== Examples

[source,shell]
----
  # Show what an endpoint here can serve
  akka optimize training endpoints info

  # Read the largest adapter rank using jq
  akka optimize training endpoints info --jq .maxAdapterRank
----
