= akka optimize training

Base models, workloads, runs, snapshots, comparisons, pipelines, evaluations, endpoints and their data

== Synopsis

A base model is what everything here trains over, and `base-models` is what this deployment allows and what you select from.
Selecting one registers it and caches its weights;
nothing holds a GPU until you ask for work.

A run trains a model from a registered dataset against a workload.
An evaluation scores a model against a dataset with a grader.
A pipeline executes curate, train and evaluate stages in one submission.
An endpoint serves a base model or a candidate at an address so you can try it by hand.

A run commits snapshots as it trains.
Snapshot weights can be registered as a model to score, or used as the source of a child run with `training runs branch`.

A session is a raw conversation corpus, and a curation judges one into a training dataset.

`capacity` reports what holds the GPU pools, which is what a queued run is behind.
`info` reports which backend the service came up on, which is what to check before a run spends anything.
