= akka eval init

Add the eval source root to a project.

== Synopsis

Writes the eval tree — scorers by family, datasets, rubrics, baselines — into the
existing project's `src/test/java` and adds the `evalkit` dependency to the project pom
at test scope. Campaigns are ordinary JUnit tests gated on `-Deval=true`, so `mvn verify`
compiles them without running them; `mvn verify -Deval=true` runs them.

Additive: a file already present is left alone and reported.
`--force` replaces existing files, after backing up what it replaces.
The dependency edit is idempotent — a pom that already declares the dependency is left
alone, and a backup is written to `pom.xml.backup` before any change.

Run the command again to take a newer scaffold; the parts you have written stay yours.

----
akka eval init [DIRECTORY] [flags]
----

== Options

----
      --force             replace files that are already there
      --from string       a scaffold archive on disk, instead of downloading one
      --package string    the Java package to write eval sources under
                          (defaults to <groupId>.eval read from the pom)
      --source string     where to download the scaffold from
  -h, --help              help for init
----

== What --package does

The scaffold ships example files under `com.example.eval.*`.
On unpack, the command rewrites that prefix to the target package so the files land under
the customer's own package on disk, and the `package` declarations plus javadoc references
inside each file are rewritten to match.

If `--package` is not given, the target is derived from the pom's `<groupId>` — for a pom
that declares `<groupId>com.acme.checkout</groupId>` the target is `com.acme.checkout.eval`
and the files land at `src/test/java/com/acme/checkout/eval/...`.
A pom that declares no `<groupId>` fails the command with a message asking for `--package`.

== What the command reports

[listing]
----
$ akka eval init
kept   src/test/java/com/acme/checkout/eval/scorer/deterministic/package-info.java
added the evalkit dependency to pom.xml (previous kept as pom.xml.backup)
run a campaign with `mvn verify -Deval=true`

Added the eval source root to . under package com.acme.checkout.eval — 7 file(s) written, 0 kept.
----

The dependency line reads `already declares the evalkit dependency` on the idempotent
path — a pom the customer has already run the command against gets no second edit.
