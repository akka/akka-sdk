= akka optimize use-cases canaries

Send a share of one use case's traffic to a candidate backend

== Synopsis

A use case canary sends a share of the conversations the live manifest matches to one label to a candidate backend, and the rest to the backend the manifest names for the label.
A change is in force at once, with no freeze and no deploy.

Promote the candidate by freezing and deploying a manifest that names it for the label.
Remove the canary to roll back.
An undeploy keeps the canaries, and they decide nothing until the next deploy.
