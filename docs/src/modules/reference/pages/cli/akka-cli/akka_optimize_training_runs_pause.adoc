= akka optimize training runs pause

Pause a run at a selected checkpoint

== Synopsis

Pause an active training run and release its compute devices and evaluation resources.

The run preserves its ID, metrics, cost accounting, and dataset progress.
When resumed, execution restarts from the checkpoint the pause stopped against.

--checkpoint states which checkpoint that is, and is required:

 latest  stop against progress the run has already confirmed, discarding the steps trained
         since that save. Refused once the run has trained without restorable state, because
         accepting it would silently restart from the base model.
 save    ask the worker to save at its next optimizer boundary and wait for that snapshot to be
         committed before it stops.

The command returns after the pause request is accepted.
Saving and device release continue, and "training runs get" reports the pause lifecycle, acknowledged saved step and whether the devices have been released.
A save that timed out or failed records its reason and never reports as successful.

Backend support for save differs by training method and profile.
An unsupported combination is refused rather than quietly downgraded to latest.
Resuming requires the same GPU device count as the run was allocated.

----
akka optimize training runs pause RUN --checkpoint latest|save [flags]
----

== Examples

----
  # Pause against the newest confirmed checkpoint
  akka-optimize training runs pause 7d496e82c3a15f04 --checkpoint latest

  # Save at the next optimizer boundary, then stop
  akka-optimize training runs pause 7d496e82c3a15f04 --checkpoint save

  # Resume the paused run
  akka-optimize training runs resume 7d496e82c3a15f04
----

== Options

----
      --checkpoint string   Which checkpoint to stop against: latest or save
  -h, --help                help for pause
----
