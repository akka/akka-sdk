= Akka Runtime 1.6.16
:page-summary: Runtime 1.6.16 raises the log severity of view update failures, fixes view field resolution and several agent defects, and updates dependencies with reported vulnerabilities.

include::ROOT:partial$include.adoc[]

Released 2026-09-02.

== Changes to existing behavior

Review these before you deploy a service on this runtime version.

* Failures in a view update handler are logged at `ERROR`. They were logged at `WARN`. Log-based alerts that filter on severity now match these failures.
* Exceptions that a view update handler does not handle are passed to the `UnhandledExceptionHandler` that your service registers. The handler was previously invoked for consumers and timed actions only.

== Bug fixes

* Views: a query field path that passes through two levels of repeated message resolves to the correct field. Such a path resolved to the wrong field before.
* Views: a `BigDecimal` column is read back from a historical view. The value was stored but not mapped on read, so it was missing from the query result.
* Agents: the configured `response-timeout` is applied for OpenAI-based model providers. Langchain4j overwrote the value with its own default, so those providers timed out after 60 seconds regardless of the configured value.
* Agents: a structured response from a Vertex AI model is parsed into the response type.
* Agents: a `null` value no longer causes a `NullPointerException` in the sanitizer.
* Agents: a name collision between an MCP tool and a built-in tool no longer hangs tool discovery. The loop that renamed the tool never terminated and exhausted the heap. A colliding name now gets the lowest free numeric suffix, so the same set of tools produces the same names on every turn. Two MCP endpoints that expose the same tool name are also disambiguated.
* Entity deletion: `TraceableAny` payloads are handled when entity data is deleted, and the Postgres delete store matches its rows more strictly.

== Security updates

Dependencies with newly reported vulnerabilities were updated.

* Netty 4.1.137.Final, for one critical and two high severity issues in `netty-handler`, one high severity issue in `netty-codec-http`, and one medium severity issue in `netty-codec-socks`.
* reactor-core 3.8.7, for two high severity issues. This is a transitive dependency, pinned by the runtime build because the fixes are released only on the 3.8.x line.
* proton-j 0.35.0, for five high severity issues. Also a transitive dependency, pinned for the same reason.

reactor-netty stays on the 1.2.x line. Its remaining fixes are released only on 1.3.x, which requires Netty 4.2, while `azure-core-http-netty`, `r2dbc-postgresql`, and the AWS SDK Netty client all still declare Netty 4.1.
