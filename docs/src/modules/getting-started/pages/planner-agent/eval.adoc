== Overview

When a coordinator task completes, the answer should be checked. This part adds an xref:sdk:evaluators.adoc[evaluator] that the runtime triggers after each interaction of the coordinator. When the interaction completed the task, the evaluator asks a judge agent whether the answer addresses the original request and respects the user's preferences, and records the verdict in the ledger.

In this part of the guide you will:

* Add a judge agent.
* Add an evaluator component that calls the judge, and bind it to the coordinator.

== Judge agent

The judge follows the pattern called "LLM as judge": an agent (AI model) evaluates the result produced by other agents. The judge looks at the original request, the user's preferences and the produced answer, and returns a typed verdict. The judge keeps no session memory, so each evaluation starts from a clean context.

The judge is a request-based xref:sdk:agents.adoc[Agent], not an `AutonomousAgent`: it does a single model call per evaluation and returns a typed result. There is no iteration loop and no multi-agent coordination, so an ordinary agent is the lighter choice.

== Evaluator

An xref:sdk:evaluators.adoc[Evaluator] is a component that the runtime triggers for the interactions of the agents it is bound to. The coordinator records one interaction per model call, and the interaction that completes the task carries a `complete_task` tool call. The evaluator reads the interaction from the ledger. When the interaction completed the task, the evaluator fetches the task result and the user's preferences, and asks the judge.

Add a new file `ActivityEvaluator.java` to `src/main/java/com/example/application/`

[source,java,indent=0]
.{sample-base-url}/multi-agent/src/main/java/demo/multiagent/application/ActivityEvaluator.java[ActivityEvaluator.java]
----
include::sdk:example$multi-agent/src/main/java/demo/multiagent/application/ActivityEvaluator.java[tag=all]
----
<1> An evaluator is a component with a `@Component` id. The id is how the configuration refers to it.
<2> The interaction under evaluation, read from the ledger with the injected `LedgerClient`.
<3> An interaction that did not complete the task, for example one that delegated to a worker, gives the evaluator nothing to judge. The evaluation ends as xref:sdk:evaluators.adoc#outcomes[not applicable].
<4> The task snapshot, for the instructions and the accepted result. A task that is not completed, for example because a task rule rejected the result, leaves the evaluation xref:sdk:evaluators.adoc#outcomes[inconclusive].
<5> The user's preferences, read from the `PreferencesEntity` with the user id from the `User: <userId>` header of the instructions.
<6> The judge runs in a session of its own, named after the evaluation.
<7> The label of the judge decides the recorded `Evaluation`. A label the evaluator does not know leaves the evaluation inconclusive.

The runtime runs the evaluator in the background after each interaction of the coordinator, so it does not delay the answer. The verdicts are recorded in the ledger and flow into the metrics and traces produced by the runtime, so dashboards and alerting can pick them up without any further wiring.

[NOTE]
====
Do not bind the evaluator to the judge agent, and give the judge no `@AgentRole` that a `*` binding matches. The evaluator's call to the judge is an interaction of the judge, which would trigger the evaluator again, without end.
====

== Running the service

Start your service locally:

[source,command line]
----
mvn compile exec:java
----

Ask for activities:

[source, command line]
----
curl -i -XPOST --location "http://localhost:9000/activities/alice" \
  --header "Content-Type: application/json" \
  --data '{"message": "I am in Madrid. What should I do? Beware of the weather."}'
----

Retrieve the suggestion (use the task id from the response):

[source, command line]
----
curl http://localhost:9000/activities/alice/{taskId}
----

Add a preference that creates a tension with the suggestion:

[source, command line]
----
curl -i localhost:9000/preferences/alice \
  --header "Content-Type: application/json" \
  -XPOST \
  --data '{
    "preference": "I dislike outdoor activities."
  }'
----

Submit the same request again. The `ActivityAgent` reads the preference, so the coordinator now produces a different answer. The evaluator reads the same preference and asks the judge whether the answer respects it. The evaluator logs each verdict, so the verdict shows up in the service log. The evaluations of the coordinator's interactions are also in the ledger, see xref:sdk:evaluators.adoc#_the_ledger_client[The ledger client].
