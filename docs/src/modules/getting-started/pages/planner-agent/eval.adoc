== Overview

When a coordinator task completes, we want to know how well the answer holds up. We will add an xref:sdk:evaluators.adoc[evaluator] that the runtime triggers after each interaction of the coordinator. When the interaction completed the task, the evaluator asks an LLM judge whether the answer addresses the original request, including any user preferences carried in it, and records the verdict in the ledger.

In this part of the guide you will:

* Add a judge agent.
* Add an evaluator component that calls the judge, and bind it to the coordinator.

== Judge agent

We will use a pattern called "LLM as judge", which uses an agent (AI model) to evaluate the result produced by other agents. The judge looks at the original request together with the produced answer and returns a typed verdict.

----

----

The judge is a request-based xref:sdk:agents.adoc[Agent], not an `AutonomousAgent`: it does a single model call per evaluation and returns a typed result. There is no iteration loop and no multi-agent coordination, so an ordinary agent is the lighter choice.

== Evaluator

An xref:sdk:evaluators.adoc[Evaluator] is a component that the runtime triggers for the interactions of the agents it is bound to. The coordinator records one interaction per model call, and the interaction that completes the task carries a `complete_task` tool call with the answer. The evaluator reads the interaction from the ledger, and when it completed the task, asks the judge.

Add a new file `ActivityEvaluator.java` to `src/main/java/com/example/application/`

[source,java,indent=0]
.{sample-base-url}/multi-agent/src/main/java/demo/multiagent/application/ActivityEvaluator.java[ActivityEvaluator.java]
----
include::sdk:example$multi-agent/src/main/java/demo/multiagent/application/ActivityEvaluator.java[tag=all]
----
<1> An evaluator is a component with a `@Component` id. The id is how the configuration refers to it.
<2> The interaction under evaluation, read from the ledger with the injected `LedgerClient`.
<3> An interaction that did not complete the task, for example one that delegated to a worker, gives the evaluator nothing to judge. The evaluation ends as xref:sdk:evaluators.adoc#outcomes[not applicable].
<4> The task snapshot, for the instructions that the endpoint built from the request and the user's preferences.
<5> The answer is the argument of the `complete_task` call.
<6> The judge runs in a session of its own, named after the evaluation.
<7> The verdict of the judge becomes the recorded `Evaluation`, with the label the judge gave.

The runtime runs the evaluator in the background after each interaction of the coordinator, so it does not delay the answer. The verdicts are recorded in the ledger and flow into the metrics and traces produced by the runtime, so dashboards and alerting can pick them up without any further wiring.

[NOTE]
====
Do not bind the evaluator to the judge agent. The evaluator's call to the judge is an interaction of the judge, which would trigger the evaluator again.
====

== Running the service

Start your service locally:

[source,command line]
----
mvn compile exec:java
----

Ask for activities:

[source, command line]
----
curl -i -XPOST --location "http://localhost:9000/activities/alice" \
  --header "Content-Type: application/json" \
  --data '{"message": "I am in Madrid. What should I do? Beware of the weather."}'
----

Retrieve the suggestion (use the task id from the response):

[source, command line]
----
curl http://localhost:9000/activities/alice/{taskId}
----

Add a preference that creates a tension with the suggestion:

[source, command line]
----
curl -i localhost:9000/preferences/alice \
  --header "Content-Type: application/json" \
  -XPOST \
  --data '{
    "preference": "I dislike outdoor activities."
  }'
----

Submit the same kind of request again (with a fresh session id). Because the endpoint includes the user's preferences in the task instructions, the coordinator now has the context it needs to produce a different answer. The evaluations of the coordinator's interactions are in the ledger, see xref:sdk:evaluators.adoc#_the_ledger_client[The ledger client].
