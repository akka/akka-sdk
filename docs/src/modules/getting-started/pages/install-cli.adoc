= Install the Akka CLI
:page-aliases: operations:cli/installation.adoc, reference:cli/installation.adoc, getting-started:quick-install-cli.adoc, operations:cli/command-completion.adoc, reference:cli/command-completion.adoc, operations:cli/system-config.adoc

The Akka CLI, `akka`, lets you interact with Akka projects, AI systems, local and remote Akka platform environments, governance bundles, and AI training runs. To install it, follow these steps:

[.tabset]
Linux::
+
--
**Recommended approach**

The recommended approach to install the `akka` CLI on Linux is using the Debian package repository:

[source,bash,subs="attributes"]
----
curl -1sLf \
  'https://downloads.akka.io/setup.deb.sh' \
  | sudo -E bash
sudo apt install akka
----

If the `akka` CLI is already installed, and you want to upgrade to the latest version, you can run:

[source,bash]
----
sudo apt update
sudo apt install --only-upgrade akka
----

**Alternative approach**

[source,bash]
....
curl -sL https://doc.akka.io/install-cli.sh | bash
....

If that fails due to permission issues, use:

[source,bash]
....
curl -sL https://doc.akka.io/install-cli.sh | bash -s -- --prefix /tmp && \
    sudo mv /tmp/akka /usr/local/bin/akka
....

You can pass options to the installer script with `-s --` e.g.:

[source,bash,subs="attributes"]
....
curl -sL https://doc.akka.io/install-cli.sh | bash -s -- --prefix=$HOME --version={akka-cli-version} --verbose
curl -sL https://doc.akka.io/install-cli.sh | bash -s -- -P $HOME -v {akka-cli-version} -V
....

--
macOS::
+
--
**Recommended approach**

The recommended approach to install `akka` on macOS, is using https://brew.sh[brew, window="new"]

[source,bash]
----
brew install akka/brew/akka
----

If the `akka` CLI is already installed, and you want to upgrade `akka` to the latest version, you can run

[source,bash]
----
brew update
brew upgrade akka
----

NOTE: Homebrew 7 and later require third-party taps to be trusted before installing or upgrading from them. If Homebrew warns that the `akka/brew` tap is not trusted, run `brew trust --formula akka/brew/akka` once and then retry.

**Alternative approach**

....
curl -sL https://doc.akka.io/install-cli.sh | bash
....

You can pass options to the installer script with `-s --` e.g.:

[source,bash,subs="attributes"]
....
curl -sL https://doc.akka.io/install-cli.sh | bash -s -- --prefix=$HOME --version={akka-cli-version} --verbose
curl -sL https://doc.akka.io/install-cli.sh | bash -s -- -P $HOME -v {akka-cli-version} -V
....
--
Windows::
+
--
**Recommended approach**

The recommended approach to install the `akka` CLI on Windows is using https://learn.microsoft.com/en-us/windows/package-manager/winget/[winget]:

[source,powershell]
----
winget install Akka.Cli
----

If the `akka` CLI is already installed, and you want to upgrade to the latest version, you can run:

[source,powershell]
----
winget upgrade Akka.Cli
----

**Alternative approach**

. Download the latest version of `akka` from https://downloads.akka.io/latest/akka_windows_amd64.zip[https://downloads.akka.io/latest/akka_windows_amd64.zip]

. Optionally, you can verify the integrity of the downloaded files using the https://downloads.akka.io/latest/checksums.txt[SHA256 checksums].

. Extract the zip file and move `akka.exe` to a location on your `%PATH%`.

--

NOTE: By downloading and using this software you agree to Akka's https://akka.io/legal/privacy[Privacy Policy] and https://trust.akka.io/cloud-terms-of-service[Software Terms of Use].

Verify that the Akka CLI has been installed successfully by running the following to list all available commands:

[source, command window]
----
akka help
----

You do not need to log in to use the CLI locally. Log in only to deploy to or manage a remote Akka Platform environment, whether it runs at akka.io or is installed in your enterprise. See xref:operations:cli/using-cli.adoc#log-in[Log in to a remote Akka environment].

[#check-version]
== Check your version

Check regularly to ensure you have the latest version of the `akka` CLI. You can check the installed version by running:

[source, shell]
----
akka version
----

[#command-structure]
== Command structure

The general structure of an Akka CLI command is:

[source, shell]
----
akka <command> [sub-command] [parameters] --[flags]
----

Flags, which modify command behavior, are always preceded by `--`.

[#command-completion]
== Enable command completion

Completion allows you to hit [TAB] on a partially entered `akka` command and have the shell complete the command, subcommand or flag for you.

[.tabset]
bash::
To load completion in the current bash shell run:
+
[source,bash]
----
source <(akka completion)
----
+
Configure bash to load `akka` completions for each session by adding the following line to your `~/.bashrc` or `~/.profile` file:
+
[source,bash]
----
# add to ~/.bashrc or ~/.profile
source <(akka completion)
----
+
[TIP]
====
Using bash completions with `akka` requires you have bash completions enabled to begin with.
Enable it in your `~/.bashrc` or `~/.profile` file with the following lines:

[source,bash]
----
if [ -f /etc/bash_completion ]; then
  source /etc/bash_completion
fi
----
For definitive details on setting up your shell with auto-completion, see the shell documentation.
====

zsh (e.g. macOS)::
To set up `zsh` shell completion run:
+
[source,zsh]
----
akka completion zsh > "${fpath[1]}/_akka"
compinit
----
+
[NOTE]
====
If shell completion is not already enabled in your environment execute the following:

[source,zsh]
----
echo "autoload -U compinit; compinit" >> ~/.zshrc
----
====

fish::
To set up fish shell completion run:
+
[source,fish]
----
akka completion fish > ~/.config/fish/completions/akka.fish
source ~/.config/fish/completions/akka.fish
----

PowerShell::
To set up shell completion for PowerShell run:
+
[source,powershell]
----
akka completion powershell | Out-String | Invoke-Expression
----

[#system-configuration]
== System configuration

The Akka CLI supports system-level configuration that allows administrators to customize CLI behavior across all users on a machine. This is useful for enterprise deployments where you want to control default settings, specify internal mirrors for templates, or disable certain features.

=== Configuration Options

The following settings can be configured at the system level:

[cols="2,3,2"]
|===
| Setting | Description | Default

| `code-templates-url`
| URL of project templates used by `akka code init`
| `\https://doc.akka.io/_attachments/akka-code-init.json`

| `context-url`
| URL of documentation context used by AI coding assistants
| `\https://doc.akka.io/java/_attachments/akka-docs-md.zip`

| `context-subdir`
| Subdirectory name where context files are stored
| `akka-context`

| `additional-constitution-url`
| URL of an organization-specific constitution, downloaded and appended to the Akka SDK constitution at `akka specify init`
| _(none)_

| `governance-policy-url`
| URL of the organization's Akka Specify governance policy (`policy.yaml` — the organization's mandatory exit conditions). Downloaded at `/akka:setup` and enforced by default; a developer's `--policy` flag cannot loosen it. See xref:reference:specify/policies.adoc[Specify policies].
| _(none)_
|===

To disable a feature, set its value to `none`. For example, setting `context-url` to `none` disables automatic context downloading.

The last two settings are the organization's governance controls for xref:sdk:spec-driven-development.adoc[Akka Specify]: `additional-constitution-url` extends the AI's guidance, and `governance-policy-url` distributes the mandatory exit-condition policy. Both use the same managed channel as the template and context settings above, so IT deploys them the same way.

=== Configuration File Locations

The CLI looks for system configuration in platform-specific locations:

[.tabset]
Linux::
+
--
[source]
----
/etc/akka/config.yml
----
--
macOS::
+
--
The CLI checks for configuration in this order:

1. MDM-managed plist (preferred for enterprise deployments):
+
[source]
----
/Library/Managed Preferences/io.akka.cli.plist
----

2. YAML configuration file:
+
[source]
----
/Library/Application Support/akka/config.yml
----

If an MDM plist is present, the YAML file is ignored.
--
Windows::
+
--
[source]
----
%ProgramData%\akka\config.yml
----

Typically this resolves to `C:\ProgramData\akka\config.yml`.
--

=== YAML Configuration Format

Create a YAML file at the appropriate location for your platform:

[source,yaml]
----
code-templates-url: https://internal.example.com/akka-templates.json
context-url: https://internal.example.com/akka-context.zip
context-subdir: akka-context
additional-constitution-url: https://internal.example.com/akka-constitution.md
governance-policy-url: https://internal.example.com/akka-specify-governance/policy.yaml
----

To disable context downloading:

[source,yaml]
----
context-url: none
----

Any settings not specified in the configuration file will use their default values.

=== macOS MDM Configuration

For macOS devices managed via Mobile Device Management (MDM), you can deploy configuration using a property list (plist) file. This is the recommended approach for enterprise macOS deployments.

Create a configuration profile with the bundle identifier `io.akka.cli` containing the following keys:

[source,xml]
----
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>code-templates-url</key>
    <string>https://internal.example.com/akka-templates.json</string>
    <key>context-url</key>
    <string>https://internal.example.com/akka-context.zip</string>
    <key>context-subdir</key>
    <string>akka-context</string>
    <key>additional-constitution-url</key>
    <string>https://internal.example.com/akka-constitution.md</string>
    <key>governance-policy-url</key>
    <string>https://internal.example.com/akka-specify-governance/policy.yaml</string>
</dict>
</plist>
----

Deploy this as a managed preference using your MDM solution.

=== Precedence

Configuration is resolved in the following order (first match wins):

1. macOS MDM plist (macOS only)
2. System YAML configuration file
3. Built-in defaults

=== Troubleshooting

If the YAML configuration file exists but contains invalid syntax, the CLI will print a warning to standard error and fall back to default values:

[source]
----
Warning: failed to parse /etc/akka/config.yml: yaml: unmarshal errors: ...
----

Verify your YAML syntax is correct if you see this warning.
