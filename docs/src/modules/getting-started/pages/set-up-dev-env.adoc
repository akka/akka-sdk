= Set up your dev env
:page-aliases: getting-started:dev-container.adoc
:page-summary: Three ways to set up an Akka development environment — with an AI harness, without AI, or in a container. Pick one; each is self-contained.
:page-persona: builder-developer, builder-ai-ml

include::ROOT:partial$include.adoc[]

There are three ways to set up an Akka development environment. Pick the one that fits how you want to work. Each path is self-contained and lists its own prerequisites.

* <<_set_up_your_ai_harness>> — install the Akka Specify Plugin and let it install and configure everything else.
* <<_set_up_your_env_without_ai>> — install the Akka CLI, Java, and Maven directly.
* <<_containerized_dev_environment>> — run everything in a Docker container, with no local Java, Maven, or CLI install.

Every tutorial and sample links back to the path it needs, so you set up once here and refer to it from everywhere else.

[#_set_up_your_ai_harness]
== Set up your AI harness

Install the Akka Specify Plugin in your AI coding assistant. From there the plugin installs and configures the rest of the tools for you.

.Prerequisites
* A supported AI coding assistant (Claude Code recommended; Akka supports 30 AI-assist tools).
* An link:https://account.akka.io/token[Akka download token, window="new"] (free).

=== Harness support matrix

Not every AI coding harness has a first-class Akka install. The matrix below groups harnesses by which install path applies.

[cols="2,1,3", options="header"]
|===
| Harness | Path | Install target

| Claude Code                            | Plugin        | `/plugin marketplace add akka/ai-marketplace` then `/plugin install akka@ai-marketplace`
| Claude Tag (Slack)                     | Plugin        | Claude Code manifest in `akka/ai-marketplace`
| OpenAI Codex CLI                       | Plugin        | `codex plugin marketplace add akka/ai-marketplace`
| Cursor                                 | Plugin or CLI init | Cursor Marketplace (search "Akka") or `akka specify init --agent cursor`
| Kiro (AWS)                             | Plugin        | Kiro Powers (search "Akka")
| GitHub Copilot (VS Code)               | CLI init      | `akka specify init --agent vscode-copilot`
| Antigravity (`agy`)                    | Plugin        | `agy plugin install https://github.com/akka/ai-marketplace`
| Any other harness with AGENTS.md support (Factory, Devin, Junie, Roo, Trae, Warp, Zed, Jules, Visual Studio 2022 Copilot, GitHub Copilot coding agent, ...) | CLI + AGENTS.md + manual MCP | `akka specify init --agent generic` writes `AGENTS.md` and `.mcp.json`; if the harness's MCP path is elsewhere, see xref:sdk:register-mcp.adoc[Register the Akka MCP server]
| Aider                                  | CLI + AGENTS.md + manual MCP | See xref:sdk:register-mcp.adoc[Register the Akka MCP server]
| Sourcegraph Cody                       | CLI + AGENTS.md + manual MCP | See xref:sdk:register-mcp.adoc[Register the Akka MCP server]
| Zed AI                                 | CLI + AGENTS.md + manual MCP | See xref:sdk:register-mcp.adoc[Register the Akka MCP server]
| Claude.ai chat (with Projects)         | CLI + AGENTS.md + manual MCP | Paste the install playbook at https://akka.ai[akka.ai, window="new"] into the project's custom instructions; MCP is admin-gated
| Any harness not listed                 | CLI + AGENTS.md + manual MCP | Same as Aider
|===

==== Installation path

* *Plugin (bundle install)* — the harness reads Akka's plugin bundle from https://github.com/akka/ai-marketplace[`akka/ai-marketplace`] and registers the full toolset (slash commands where supported, MCP server, SDK context).
* *CLI init (`akka specify init --agent <harness>`)* — no bundle for this harness; the Akka CLI writes the harness's own native rules or instructions file plus its MCP config.
* *CLI + AGENTS.md + manual MCP* — fallback for harnesses without a plugin bundle and without a CLI agent profile. Install the CLI, register the MCP server by hand, keep `AGENTS.md` at the project root.

NOTE: The Akka CLI's `--agent` profiles today are `claude-code` (default), `cursor`, `vscode-copilot`, and `generic` (see xref:reference:cli/akka-cli/akka_specify_init.adoc[akka specify init]). Every other harness in the "CLI + AGENTS.md + manual MCP" rows uses `--agent generic`, which writes a harness-agnostic `AGENTS.md` plus `.mcp.json`. Where the harness looks for MCP configuration at a different filename (Zed, Cody, etc.), follow the manual step in xref:sdk:register-mcp.adoc[Register the Akka MCP server] after `akka specify init --agent generic`. Additional per-harness profiles are on the roadmap; they will appear in this table as the CLI ships them. The canonical `AGENTS.md` template is published at https://doc.akka.io/sdk/_attachments/AGENTS.md[doc.akka.io/sdk/_attachments/AGENTS.md, window="new"] so `akka specify init` and manual setups reference the same file.

For AI-driven installs, the human-facing entry point is https://akka.ai[akka.ai, window="new"] — paste "install Akka from akka.ai" into any supported harness and it walks the flow above.

=== Configure your environment

[source]
----
/akka:setup
----

This ensures the Akka CLI is installed, Java and Maven are available, and your Akka download token is configured.

=== Choose your mode

The Akka Specify plugin runs in one of two modes:

* *À la carte* (the default) lets you run the specification commands individually, with nothing blocking you -- faster and lighter.
* *Enforced* makes you define "done" as machine-checkable exit conditions before code is written, and gates shipping until they are met -- a cleaner, auditable result. Opt in when you want that rigor.

New installs start in *À la carte* mode. Switch at any time:

[source]
----
/akka:mode a-la-carte
/akka:mode enforced
----

See xref:sdk:spec-driven-development.adoc#choosing-your-mode[Choosing your mode] for the trade-offs. Then build your first agent with the xref:getting-started:spec-your-first-agent.adoc[Spec-first hello agent] tutorial, which walks the same build in either mode.

== Set up your env without AI

Install the tools directly on your machine. Use this path if you do not want an AI harness, or your AI-assist tool does not support plugins.

* Java {java-version} (see https://adoptium.net/marketplace/[Adoptium, window="new"]).
* Apache Maven {minimum_maven_version} or later.
* An link:https://account.akka.io/token[Akka download token, window="new"] (free).

=== Create a project

Create a new project from a sample and start building:

----
akka code init --name helloworld-agent --repo akka-samples/helloworld-agent.git

[#_containerized_dev_environment]
== Containerized dev environment

Run Akka inside a pre-built Docker container. Nothing but Docker is installed on your machine — the container bundles Java {java-version}, Maven, the Akka CLI, and pre-cached SDK dependencies.

.Prerequisites
* https://www.docker.com/products/docker-desktop/[Docker Desktop, window="new"].
* An link:https://account.akka.io/token[Akka download token, window="new"] (free).

=== Set environment variables

The download token is required. AI provider keys are optional and only needed for agent samples.

[source,bash]
----
export AKKA_RESOLVER_TOKEN=<your-token>       # required
export GOOGLE_AI_GEMINI_API_KEY=<your-key>    # optional, for agent samples
export ANTHROPIC_API_KEY=<your-key>           # optional, for agent samples
export OPENAI_API_KEY=<your-key>              # optional, for agent samples
----

=== Create a project and start the container

. Create a new project from a sample:
+
[source,bash]
----
akka code init --name helloworld-agent --repo akka-samples/helloworld-agent.git
----
. Start the dev container with the project directory mounted:
+
[source,bash]
----
docker run -d --name akka-dev \
  -v "$(pwd)/helloworld-agent":/workspace \
  -p 9000:9000 \
  -p 9889:9889 \
  -e AKKA_RESOLVER_TOKEN \
  -e GOOGLE_AI_GEMINI_API_KEY \
  -e ANTHROPIC_API_KEY \
  -e OPENAI_API_KEY \
  registry.akka.io/akka-dev-container:latest
----
+
This forwards `localhost:9000` for your service endpoint and `localhost:9889` for the Akka local console.

=== Run the service

Build commands run inside the container with `docker exec`; your files stay on the host through the bind mount.

[source,bash]
----
docker exec -w /workspace akka-dev mvn compile exec:java
----

Test it from your host:

[source,bash]
----
curl -i -XPOST http://localhost:9000/hello \
  --header "Content-Type: application/json" \
  --data '{"user": "alice", "text": "Hello, I am Alice"}'
----

Start the local console with `docker exec -t -w /workspace akka-dev akka local console --bind-address 0.0.0.0`, then open http://localhost:9889[localhost:9889, window="new"].
