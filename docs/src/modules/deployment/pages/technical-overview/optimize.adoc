The model routing, serving and training add-on is a set of infrastructure and service extensions for multi-model routing, inference for self-hosted models, training and testing small language models, and cost management. You add it to an existing AAO environment. It uses the same federation and application planes, command and control, communications, security, compliance, data protection, and monitoring infrastructure that AAO already installs. See xref:deployment:technical-overview.adoc[How AAO works] for that architecture.

== What Akka installs

Akka installs open source infrastructure in the Kubernetes cluster that AAO uses. The installation is the same for BYOC and BYOK8s.

[cols="1,3", options="header"]
|===
| Component | Role

| vLLM
| Hosts models and runs inference.

| agentgateway
| Routes requests across multiple models.

| KubeRay
| Runs training jobs and serves models.

| NVIDIA device plugins
| Schedules GPUs.

| verl
| Runs reinforcement learning for sharded and multi-device training runs. Also scores and grades training runs.
|===

Akka also provisions the storage account (bucket) for training. The add-on stores logs and traces of AI interactions in your hyperscaler's preferred object storage service. The flows that Optimize adds are in the xref:deployment:technical-overview/data-flows.adoc[data flows].

== What the add-on needs from you

* A GPU capacity reserve that is integrated into the add-on. Your Akka team shows you how to configure it.
* BYOK8s only: a node pool in your existing Kubernetes environment, dedicated to routing and inference.

== Models and routing

You deploy a model onto GPU capacity in an Akka region. Any OpenAI-compatible client can call it, from inside an Akka project or from the internet. You can deploy three kinds of model:

* A public open-weights model.
* Your own small language model, private to you.
* A public base model with your own low-rank adaptation (LoRA) adapter on top, served under its own name.

Akka installs and manages the routing and serving components separately from the training components. Initially, a deployment gives you direct access to manage routing and inference. For how-to guides, see xref:inference:serving/getting-started.adoc[] and xref:inference:routing.adoc[]. Akka's team configures and manages the initial training loops with you, while Akka stabilizes the external interfaces that define and run long-running training loops.
