Dedicated runs your Akka services in a single-tenant region in Akka's cloud account. Akka Automated Operations (AAO) operates the region, and no other organization's workloads run in it.

== How Dedicated works

Akka prepares the cloud account and installs the region. There are no setup steps for you: you do not provision a cloud account, a Kubernetes cluster or a database.

The architecture is the BYOC architecture, in Akka's account instead of yours. The region has the same Federation Plane and Application Plane, the same security and backups, and the same automation. See xref:deployment:technical-overview.adoc[How AAO works] for that architecture. Because Akka owns the account, Akka also operates the network around the region: address ranges, peering, allowlists and DNS.

== Private data link

A Dedicated region can connect to your own network through a private data link, for example a transit gateway. Traffic between your network and the region then stays off the public internet. Akka operates connectivity inside its own network, and you and Akka coordinate on the integration with yours. BYOC does not need a private data link, because a BYOC region already runs in your account.
