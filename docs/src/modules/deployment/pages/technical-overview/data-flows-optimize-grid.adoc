= Akka Optimize data flows
:page-layout: dense
:page-breadcrumb: Akka / Deployment / How AAO works / Data flows / Akka Optimize
:page-return-to: data-flows.html
:page-summary: The network flows that Akka Optimize adds to an Akka Automated Operations region, in one filterable grid, with the status of each flow.

Akka Optimize adds these flows to the xref:deployment:technical-overview/data-flows-grid.adoc[platform data flows].

[.dense, cols="2,4,3,2,2,3,3,4", options="header"]
|===
| Actor | Flow | What data | From | To | Connectivity | Auth | Notes

8+h| AI gateway

| End users and third-party agents | Inference call from outside the region (third-party agent or end user) | Prompts, messages, tool definitions, completions (streamed), embedding input | External client | Route hostname, then Contour, then agentgateway | [.conn-public]#Public# to the region ingress; private and mesh mTLS inside. Contour Envoy (TLS), then gateway port 80 inside the mesh | TLS at ingress (optional client certificate, optional JWT validation on the route); mandatory Bearer API key at the gateway | Request parameters are allowlisted per API; `+guided_*+` and `+model_revision+` are rejected
| Deployed Akka services | Inference call from an Akka agent in the same project | Prompts and completions | Your service pod | `+http://<endpoint>.<project>.svc.cluster.local/v1+`, routed to agentgateway | [.conn-private]#Private# mesh mTLS (In-cluster service name) | Bearer API key | In-cluster access needs a change to the gateway network policy. Until then, Akka agents call the endpoint through its route, as in the inference call from outside the region.
| Akka Region (AI gateway) | Gateway dispatches to the model engine | Request and response bodies | agentgateway | vLLM engine port 8000 | [.conn-private]#Private# mesh mTLS (Pod to pod) | Linkerd mesh policy admits only the gateway's mesh identity on port 8000 | The Kubernetes network policy admits the gateway and monitoring pods. The mesh policy, not the network policy, blocks other pods in the same namespace.
| Akka Region (AI gateway) | Gateway configuration | API keys, routing tables | agentgateway controller | agentgateway proxies | [.conn-private]#Private# (xDS over TLS) | Kubernetes RBAC | API keys are stored as Kubernetes Secrets in the project
| Akka Region | Usage metering | vLLM metrics labelled with model, billing ID, accelerator type and memory; no prompts or completions | Prometheus | Engine `+/metrics+` | [.conn-private]#Private# then the existing region observability path (In-cluster scrape) | Network policy | Covers in-region serving only. Spend on external providers is metered from captured traffic.
| Deployed Akka services (Optimize) | Optimize services look up the caller's project roles | Caller's Akka access token (forwarded), project ID | optimize, optimize-training, optimize-registry, portfolio, gateway-router, offline-evaluation | Akka management API | [.conn-public]#Public#. HTTPS egress from the project namespace | Caller's Akka access token; answers cached 5 minutes | New egress from the region to Akka. Add the Akka API hostname to the egress allowlist.

8+h| Routing gateway

| Deployed Akka services (Optimize) | Routing gateway sends requests to a frontier model provider | Prompts and completions | Optimize routing gateway (agentgateway in the router namespace) | OpenAI API | [.conn-public]#Public# (Project egress) | Provider API key stored as a Kubernetes secret in the router namespace | Data leaves the region to the provider you select
| Deployed Akka services (Optimize) | Capture of routed traffic for training and evaluation | Captured LLM requests and responses | gateway-router, capture-refinery | Project storage account (`+captured/+`, `+normalized/+`) | *Azure-specific:* [.conn-private]#Private# if a private endpoint is configured (Azure Storage endpoint) | *Azure-specific:* Per service: Azure shared key, SAS, or Azure default credential. | Captured prompts and completions are sensitive data.
| End users, third-party agents, and Akka agents | Inference call to the Optimize routing gateway | Prompts and completions | Client | Optimize routing gateway (agentgateway in the router namespace) | Load balancer of the router namespace |  | Separate gateway from the platform inference gateway.
| Akka Region (routing gateway) | Routing gateway asks gateway-router for a routing decision | Request body, up to 2 MiB | Routing gateway | gateway-router service (external processor, gRPC) | [.conn-private]#Private# (In-cluster) |  | Configured fail-open: if gateway-router fails, the request continues without a routing decision.
| Akka Region (routing gateway) | Routing gateway sends requests to an in-region model | Prompts and completions | Routing gateway | In-region model endpoint (fine-tuned model) | [.conn-private]#Private# (In-cluster) | Model endpoint API key | Traffic stays in the region.
| Deployed Akka services (Optimize) | capture-refinery normalizes captured traffic and reports usage | Captured requests and responses; token usage | capture-refinery | Storage account (`+normalized/+`) and portfolio service | *Azure-specific:* [.conn-private]#Private# (Azure Storage endpoint; in-cluster) | Per service storage identity | Usage feeds cost governance in portfolio.
| Deployed Akka services (Optimize) | Offline evaluation calls an external judge model | Evaluation prompts and model outputs | offline-evaluation | Google Gemini or OpenAI API | [.conn-public]#Public# (HTTPS egress) | Provider API key, stored as an Akka secret | Evaluation data leaves the region to the provider.

8+h| Model serving and GPUs

| Developers | Declare models, endpoints, and GPU allocations | Model spec (Hugging Face repo and SHA, secret names, engine arguments), endpoint spec, allocation | Developer (CLI) | Region Kubernetes API, through the existing Akka control channel | [.conn-private]#Private# (peering), as for deploying a service | Akka RBAC: `+project.models.*+`, `+project.modelEndpoints.*+`. Inference must be enabled for the organization or the project. | Platform-owned vLLM flags (`+--api-key+`, `+--trust-remote-code+`, `+--download-dir+`, `+--host+`, `+--tokenizer+`, `+--chat-template+`) are refused
| Akka Federation Plane / Region | Sync accelerator pools and entitlement | Pool definitions (driver, product, memory, tolerations); `+inference_enabled+` | Akka Federation Plane | Region | [.conn-public]#Public# outbound TLS tunnel from the region (Teleport agent) | Teleport mutual TLS certificates | No new connection. Uses the existing Teleport tunnel.
| Akka Region (model serving) | vLLM downloads base model weights at start | Model weights, config, tokenizer | vLLM engine pod | huggingface.co | [.conn-public]#Public# (HTTPS egress) | Hugging Face token from a project secret (env var) | Pinned to a commit SHA; cached on a PVC if configured
| Akka Region (model serving) | Fetch LoRA adapters | Adapter weights | Init container | huggingface.co (pinned SHA) | [.conn-public]#Public# (HTTPS egress) | Hugging Face token | *Azure-specific:* Object-storage adapters are S3 only and not available on Azure
| Akka Region (model serving) | GPU binding | None (device allocation) | Kubernetes scheduler | GPU node | DRA ResourceClaim | Claim belongs to one project namespace | Models in one project that share a device index share one GPU by time-slicing. Each engine limits its own GPU memory use through vLLM configuration. The GPU does not enforce the limit.
| Akka Region | Image pulls | vLLM, agentgateway, training runtime, Optimize service, and OpenTelemetry Collector images | Kubelet | Akka image registry, or your mirror | [.conn-public]#Public# or private to the mirror (Node egress) | Registry pull secret | Images in Akka's private registry need Akka-issued pull credentials for your mirror. The OpenTelemetry Collector image comes from Docker Hub.
| Akka Region (model serving) | vLLM usage statistics | Anonymous usage data (hardware, model architecture) | vLLM engine pod | vLLM usage statistics endpoint | [.conn-public]#Public# (HTTPS egress) | None | vLLM sends usage statistics by default.

8+h| Training, datasets, and registry

| Developers | Upload a dataset | Chat JSONL, images, evaluation items, Parquet. *Azure-specific:* Up to 256 MiB per upload on Azure with workload identity (configurable). | User (CLI or API) | optimize-registry, which writes to `+objects/{sha256}+` in the storage account | [.conn-public]#Public# to ingress (TLS); service to storage as in the training job storage flow (Akka route `+/v1/registry+`) | Akka platform JWT; any project role can upload | Content-addressed storage. Any project role can upload. No delete API.
| Developers | Upload a scoring bundle | Your grader and reward code (Python ZIP) and data | User | Storage account `+bundle-archives/+` | As for dataset upload (Akka route `+/v1/registry+`) | As for dataset upload | Bundle code runs inside training jobs with the job's identity and network access. Bundles are checked by digest. Treat bundles as trusted code.
| Developers | Upload captured conversations for curation | Production conversations | User | optimize-training, storage account | As for dataset upload (`+/v1/training/sessions+`) | As for dataset upload | Automated curation uses an external LLM judge and is disabled; with it disabled, nothing leaves the region
| Developers | Import an adapter trained elsewhere | LoRA weights | User | Storage account `+adapter-imports/+` | As for dataset upload (`+/v1/training/adapters/imports+`) | As for dataset upload | Provenance of imported weights is your responsibility
| Akka Region (training) | Training service submits a job to Ray | Job spec, run config, storage URIs | optimize-training | Ray head `+trainer-head-svc:8265+` | [.conn-private]#Private# in-cluster (project namespace to `kuberay`) (Ray job submission API) | Kubernetes NetworkPolicy admits listed client pods only | 
| Akka Region (training) | Training job reads data and writes checkpoints and adapters; serving loads adapters | Datasets, scoring bundles, tokenized rows, checkpoints (adapter, optimizer state; about 2.4 GB per save), trained adapters, TensorBoard events | Ray job / Ray Serve | Training storage account (`+abfss://{container}@{account}.dfs.core.windows.net+`) | *Azure-specific:* [.conn-private]#Private# if you configure a private endpoint; nothing in Akka forces one (Azure Storage endpoint) | *Azure-specific:* Azure workload identity (service account trainer-ray), no static keys | Encryption at rest is the storage account's (managed by you, customer-managed key possible). Snapshots are removed by retention; exported adapters are not deleted.
| Akka Region (training) | Download base model weights | Open model weights and tokenizer files | Ray job / Ray Serve | huggingface.co, cached on an RWX volume | [.conn-public]#Public# (HTTPS egress) | Hugging Face token (Kubernetes Secret) | Requires egress allow-list for huggingface.co, or a pre-filled cache
| Akka Region (training) | Resolve base model commits | Repository names, revisions | optimize-training, optimize-registry | huggingface.co | [.conn-public]#Public# (HTTPS egress) | Hugging Face token | Training service does not start if the hub is unreachable
| Developers | Inference against trained candidates | Prompts and completions | User via `+/v1/training/endpoints/.../chat/completions+` | Ray Serve `+trainer-serving-head-svc:8000+` | [.conn-public]#Public# to ingress (TLS), private in-cluster | Akka platform JWT at ingress | Separate from production serving
| Akka Region (training) | Grader / reward callback | Model outputs to score | Ray job | optimize-training `+/internal/grader+` | [.conn-private]#Private# (In-cluster) | Run-scoped signed token | Not exposed through the Akka route
| Akka Region (training) | Training metrics export (off by default) | Ray and training metrics; namespace, pod, node labels | OpenTelemetry collector sidecar | Akka metrics endpoint | [.conn-public]#Public# same path as existing region observability (HTTPS egress) | mTLS client certificate | Traces are not exported
| Developers | User downloads run observations | TensorBoard events, job logs, rollouts (model generations over your prompts) | User | User machine | [.conn-public]#Public# (TLS) (Akka ingress) | Akka platform JWT; readers can download | Logs and rollouts can contain your data
| Deployed Akka services (Optimize) | Optimize services read and write the storage account | Datasets, registry metadata, captured traffic, evaluation data | optimize-training, optimize-registry, gateway-router, capture-refinery, offline-evaluation | Training storage account | *Azure-specific:* [.conn-private]#Private# if you configure a private endpoint (Azure Storage endpoint) | *Azure-specific:* Per service: Azure default credential, shared key, or SAS. | Each service needs its own storage identity.
| Akka Region (training) | Ray usage statistics | Anonymous cluster usage data | Ray head | Ray usage statistics endpoint | [.conn-public]#Public# (HTTPS egress) | None | Ray reports usage statistics by default.
| Akka Region | Helm chart pulls at install | agentgateway and training Helm charts | Akka installer | Akka OCI chart registry, or your mirror | [.conn-public]#Public# or private to the mirror (Registry egress) | Akka-issued registry credential | Charts must be added to your mirror.

8+h| GPU provisioning

| Akka SRE / Federation Plane | Declare accelerator pools for the region | Pool name, GPU product, memory, MIG profile, tolerations | Akka SRE, via the region definition in the Federation Plane | Region (DeviceClass) | [.conn-public]#Public# outbound TLS tunnel from the region (Teleport agent) | Akka SRE access to the Federation Plane; Teleport mutual TLS to the region | Pools are removed from the region when removed from the definition
| Developers | Allocate GPUs to a project | Pool name, number of devices | Developer (CLI) | Region (ResourceClaims in the project namespace) | [.conn-private]#Private# (peering), as for deploying a service | Akka RBAC | A model allocation belongs to one project. The Ray training and serving clusters are shared across the region and claim GPUs outside per-project allocations.
| Akka Region (GPU) | GPU device inventory | Device attributes (product, memory) | NVIDIA DRA driver | Kubernetes API | [.conn-private]#Private# (In-cluster) | Kubernetes RBAC | None
|===
