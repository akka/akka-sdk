Every system you build with Akka runs on the Akka runtime. The runtime is the same wherever it runs, so your services are the same code in every deployment option. What changes between options is who operates the runtime and the infrastructure under it.

== The runtime

Akka keeps state together with the code that owns it. Instead of stateless services on one side and a database on the other, each component holds its own state in memory and records every change durably as events and snapshots. The application is its own system of record. When a process or node fails, the runtime rebuilds the state of each component from its events, with no operator action.

Services form a cluster with no primary node. State is sharded across the nodes, each entity has one owner at a time, and requests are routed to the owner wherever it runs. As nodes join or leave, shards rebalance. Nodes communicate over encrypted gRPC without a message broker, and split-brain resolution keeps the cluster consistent when the network partitions.

A project can span several regions, clouds and data centers as one system. State is replicated to every region, reads are served locally, and you choose how writes are handled in each region. You can filter what is replicated, and keep data in the regions where it is allowed to live.

See xref:concepts:deployment-model.adoc[], xref:concepts:state-model.adoc[] and xref:concepts:multi-region.adoc[].

Serverless is pay as you go, billed to a credit card, and scales to zero when idle. You create an account at console.akka.io and deploy from the Akka CLI.

In BYOC and BYOK8s, application data stays in your environment. A limited set of platform interactions, such as deployments and key rotation, still crosses to Akka. See xref:operations:technical-overview.adoc[] for the architecture and data flows, and xref:operations:production-readiness/choosing-your-environment.adoc[] for sizing, availability and data residency.

== What Akka Automated Operations does

Akka Automated Operations (AAO) runs the runtime for you in the Serverless, Dedicated, BYOC and BYOK8s options. It handles the work that comes after deployment:

* Elastic scaling: capacity follows load, idle services scale to zero, and cold starts are handled.
* Multi-region operations: one system across regions, with failover when a region is lost.
* No-downtime updates: new versions roll out in waves, including changes to how services store data.
* Live patching: runtime and security patches, and certificate and key rotation, without downtime.
* Moving between environments: cloud to cloud, from Akka's cloud into your own account, or back on premises, by replication with an automated switch.
* Multi-tenancy and zero-trust networking: tenants are isolated, and every workload is attested rather than trusted for its network location.
* Observability: logs, metrics and traces, exported to OpenTelemetry, Prometheus or Splunk.
* Operations around the clock by Akka for the options Akka operates.

Self-managed operations give you the runtime, clustering, elasticity and resilience. The other items above are AAO. See the feature comparison on xref:operations:index.adoc[Operating].
