Governance connects a system's obligations to the controls that run and the evidence they produce. Akka applies controls in the runtime that executes agent interactions, rather than relying only on observations after completion.

== Enforcement and observation

A guardrail can stop a model or tool call before it happens. A sanitizer can mask text before it reaches a model or log. An evaluator assesses completed behavior. These act at different times; an observation made after a reply cannot change that reply.

The runtime also knows which tools it invoked and which workload acted. That connects evidence to execution rather than recording only what a model proposed to do. Durable processes can wait for human decisions without losing progress across restarts.

== Linking obligations to running controls

Each control has an identifier. Configuration binds that identifier to an enforcement or evaluation mechanism, and recorded verdicts identify the control that produced them. This lets reviewers connect the requirement, the configured check, and the observed result.

The runtime records its configured controls at startup. A missing or inconsistent identifier weakens the connection between policy and evidence even when the underlying check still runs.

== Runtime scope and external agents

Controls acting inside an Akka interaction depend on that runtime's execution boundaries. Agents built elsewhere can supply traces or captured model traffic for assessment, but that does not give Akka the same ability to stop their internal actions or attest their complete execution.

Evidence supports compliance decisions; it does not make a risk assessment complete or replace the people responsible for accepting controls and reviewing changes.
