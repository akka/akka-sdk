Serving a model means running it on hardware in your project and exposing it on a hostname that OpenAI-compatible clients can call. Akka runs the model, allocates the hardware it needs, and provisions a TLS certificate for the hostname.

You describe what you want to run in a model descriptor, a YAML file that declares three kinds of resource. Applying that file is what creates them.

[cols="1,3", options="header"]
|===
| Resource
| What it declares

| `AcceleratorAllocation`
| A number of devices that your project claims from one of the region's accelerator pools.

| `Model`
| One checkpoint, the engine that serves it, and the allocated device it runs on.

| `ModelEndpoint`
| The models that one endpoint serves, and the secret that holds its API keys.
|===

Applying a descriptor writes these in dependency order, so nothing refers to a resource that does not exist yet: allocations, then models, then endpoints. See xref:reference:descriptors/model-descriptor.adoc[Model descriptor] for every field of every resource.

A model descriptor does not hold secrets or routes. Create the secrets that the models need, such as the token for gated weights and the endpoint's API keys, with `akka secrets` and `akka models endpoints keys`. A project route puts an endpoint on a hostname.

== Serving a model for the first time

xref:inference:serving/getting-started.adoc[Serving your first model] is a tutorial that does all of this in one pass. The pages below describe each step in detail, in order. The result is a model answering requests on a hostname, with a key that authorizes them.

. xref:inference:serving/reviewing-hardware.adoc[Reviewing available hardware] shows the accelerator pools that your region offers.
. xref:inference:serving/allocating-hardware.adoc[Allocating hardware to models] claims devices from a pool.
. xref:inference:serving/deploying-models.adoc[Deploying models] declares the model, applies the descriptor, and waits for the model to become ready.
. xref:inference:serving/exposing-models.adoc[Exposing models on a hostname] puts the model behind a URL.
. xref:inference:serving/issuing-api-keys.adoc[Issuing API keys] authorizes clients to use that URL.
. xref:inference:serving/calling-a-model.adoc[Calling a deployed model] sends the first request.

xref:inference:serving/removing-deployments.adoc[Removing deployments] covers tearing down what you created.

== Serving and routing

Serving decides what runs. xref:inference:routing/index.adoc[Routing requests to models] decides which of several providers answers a given request, and a model you serve yourself is one destination a route can name. The two are independent: a served model is reachable on its own hostname whether or not any route names it.
