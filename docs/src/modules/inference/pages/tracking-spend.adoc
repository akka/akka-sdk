= Tracking inference spend
:page-summary: Inference spend is the cost of the model traffic in a period and the tokens it consumed, computed from recorded exchanges and priced from a versioned pricing catalog.
:page-persona: builder-ai-ml, operator
:page-banner: inference

include::ROOT:partial$include.adoc[]

Inference spend is the cost of the model traffic in a period, together with the tokens that traffic consumed. An exchange is one request to a model and the response that the model returns. The gateway router records each exchange, and Akka computes spend from the recorded exchanges. The portfolio service prices each exchange when it stores the exchange, at the rate that the pricing catalog holds for the instant the exchange was served. If the served name has no price at that time, the service prices the exchange later, once a published price covers the instant it was served.

Two command groups work together. `akka optimize pricing-catalog` publishes the prices, and `akka optimize spend` reads the figures computed from them. Each price belongs to a served name: the model name that the provider reports in the `model` field of its response, for example `claude-sonnet-5-5`. Publish a price for each served name before your services send traffic to that model. An exchange that has no price counts in the token totals and adds nothing to the spend. When traffic is recorded before its served name has a price, the service prices it after you publish a price that takes effect at or before that traffic. See <<unpriced>>.

== Before you begin

include::partial$portfolio-service-address.adoc[]

Reading prices and spend needs read access to the Akka Optimize portfolio. Publishing prices, including a dry run, needs write access.

Spend has figures only for traffic that the gateway router recorded. Traffic that was not recorded does not appear. See xref:inference:routing.adoc[Routing requests to models] for how requests reach the gateway router.

[#publish-prices]
== Publish prices

The pricing catalog holds the price of each served name as rates per million tokens. A response without a `model` field is unpriced.

The catalog is versioned. A published version is never edited, so an exchange that a version priced keeps that price. To change a price, publish a new version that takes effect later.

=== Write a catalog document

A catalog document is JSON:

[source,json]
----
{
  "effectiveAt": "2026-09-15T16:00:00Z",
  "source": "list prices",
  "models": [
    {
      "model": { "provider": "example", "name": "frontier", "version": "1" },
      "servedName": "frontier-model",
      "assigned": false,
      "currency": "USD",
      "input": 5.00,
      "output": 25.00
    },
    {
      "model": { "provider": "example", "name": "finetune", "version": "1" },
      "servedName": "finetune-model",
      "assigned": true,
      "currency": "USD",
      "input": 0.10,
      "output": 0.30,
      "cacheRead": 0.01
    }
  ]
}
----

[cols="1,3", options="header"]
|===
| Field
| Meaning

| `effectiveAt`
| Required. The ISO-8601 instant in UTC from which the prices apply. It must be later than the latest price of every served name that the document carries. It can be in the future or in the past. When the document holds the first price of a served name and `effectiveAt` is in the past, that price also prices the recorded traffic of the served name from that instant on. A later price with a past `effectiveAt` does not change traffic that an earlier price covered.

| `source`
| Optional. Free text that records where the prices came from.

| `model`
| Required. The `provider`, `name`, and `version` of the model.

| `servedName`
| Required. The served name that this price applies to. A served name can appear once in a document.

| `assigned`
| Optional. `true` when your organization set the rate, for example a negotiated rate. `false` for a list price. Defaults to `false`.

| `currency`
| Required. An upper-case ISO 4217 code, such as `USD`. The catalog holds one currency. A document that introduces a second currency is refused.

| `input`, `output`
| Required. The rate per million input and output tokens.

| `cacheRead`, `cacheWrite`, `reasoning`
| Optional. The rate per million tokens of these classes.
|===

An exchange is priced only when every token class that it used has a rate. A rate that you leave out means the class has no price, not that it costs nothing. If a model does not charge for a class, set its rate to `0`. If you leave out `cacheRead` for a model whose traffic uses cached input, that traffic is unpriced.

A version can price some served names and leave out others. The served names that it leaves out keep their earlier price.

Change the example before you publish it:

* Keep only the models that your traffic uses. Each `servedName` must be the string that your provider's responses report in their `model` field. OpenAI responses report the dated snapshot, such as `gpt-5.4-mini-2026-03-17`, also when the request names `gpt-5.4-mini`. To see the served names that your traffic reports, divide a recent period by `model`, as in <<read-spend>>. Add an entry for each served name in that division that has no price yet.
* Set `effectiveAt` to the instant from which the prices apply, and `source` to where they came from.
* Where your organization has a negotiated rate, state that rate and set `assigned` to `true`.

Check the document with `--dry-run` before you publish it.

=== Check and publish

Check a document without publishing it:

[source,shell]
----
akka optimize pricing-catalog apply -f catalog.json --dry-run
----

The service validates the document and states the version it would publish. Nothing is written.

Publish it:

[source,shell]
----
akka optimize pricing-catalog apply -f catalog.json
----

The command asks you to confirm. Pass `--force` to skip the question in a script. To read the document from standard input, pass `-f -`. Without a terminal, publishing requires `--force`, `--disable-prompt`, or `AKKA_DISABLE_PROMPTS=true`; otherwise, the command stops without publishing.

A document that the service refuses is not published, and the error names what is wrong, for example a rate that is missing or negative, or an `effectiveAt` that is not later than the latest price.

=== Read the catalog

Read the version in force now:

[source,shell]
----
akka optimize pricing-catalog get
----

[source,text]
----
Version       1
Effective at  2026-09-15T16:00:00Z
Published at  2026-09-15T15:58:12.353062Z
Source        list prices
SERVED NAME     MODEL                CURRENCY  ASSIGNED  INPUT  CACHE-READ  CACHE-WRITE  OUTPUT  REASONING
frontier-model  example/frontier/1   USD       no        5      —           —            25      —
finetune-model  example/finetune/1   USD       yes       0.1    0.01        —            0.3     —
----

A class with no price shows `—`. Pass `--at` with an ISO-8601 instant to read the version that was in force at that time.

`get` shows one version: the latest one in force at that instant. If that version priced only some served names, the prices that earlier versions set for the other names still apply, but `get` does not show them. List the versions to see them all:

[source,shell]
----
akka optimize pricing-catalog versions list
----

The list is newest first.

[#read-spend]
== Read spend for a period

A period is a window of whole UTC hours. `--from` is inclusive and `--to` is exclusive. The service refuses a window that is not whole hours, or whose end is not after its start.

[source,shell]
----
akka optimize spend get --from 2026-09-15T16:00:00Z --to 2026-09-15T17:00:00Z
----

The answer gives the number of exchanges, the tokens, the spend, and what is unpriced. It also states whether the figures are complete:

* `complete`: every hour of the window has been reported on, and no exchange was lost.
* `incomplete`: some hours have not been reported on yet, for example because the window includes the current hour, or some exchanges were lost.
* `unknown`: no hour of the window has been reported on yet.

Money is reported with the digits that the service computed. A figure that has no value says why, and never reads as zero.

=== Divide the period

Pass `--by` to divide the period into rows. The rows always add up to the total.

[source,shell]
----
akka optimize spend get --from 2026-09-15T16:00:00Z --to 2026-09-15T17:00:00Z --by model
----

[source,text]
----
MODEL           EXCHANGES  TOKENS  SPEND                   UNPRICED  UNPRICED TOKENS
frontier-model  69         1575+   0.0255750000000000 USD  0         0
finetune-model  12         285+    0.0000615000000000 USD  0         0
TOTAL           81         1860+   0.0256365000000000 USD  0         0
----

[cols="1,3", options="header"]
|===
| `--by`
| One row for each

| `model`
| Served name.

| `useCase`
| Use case that the gateway router assigned. See xref:inference:routing.adoc[Routing requests to models].

| `model,useCase`
| Combination of the two.

| `caller`
| Caller, ranked, with one row for the remainder. `caller` cannot be combined with other divisions.
|===

`--limit` sets how many rows a ranked division returns. The service sets the default.

A `+` after a token count marks a lower bound: some exchanges did not report every token class, so the true count can be higher. This is common, because providers do not report every class. For example, OpenAI responses do not report cache-write tokens, and Anthropic responses do not report reasoning tokens. The command prints a note that names the classes that were not reported.

[#unpriced]
=== Find unpriced traffic

An exchange is unpriced when no price covers every token class that it used. It counts in the exchanges and tokens, and not in the spend. When a period has unpriced traffic, the answer states the cause: a served name with no price, or a token class with no rate. Divide by `model` to see which served names have unpriced traffic. Publish a catalog version that adds the price or the missing rate.

Which unpriced traffic the new version prices depends on the cause:

* A served name with no price. The service prices the recorded traffic of that served name that was served at or after the `effectiveAt` of the new price. To price traffic that is already recorded, set `effectiveAt` at or before its earliest exchange. The service prices the first exchanges shortly after the publish, and a long range takes longer. The service keeps the record of each exchange for at least 90 days. Older traffic keeps its figures and remains unpriced.
* A token class with no rate. The exchange keeps the version that priced its served name, and that version has no rate for the class. The new rate applies only to traffic served after the new version takes effect and recorded after it is published. Traffic recorded before that remains unpriced.

The spend of a period can rise after a publish, and its unpriced count fall, also when the period is `complete`.

=== When a price changes during a period

A period that spans a price change holds exchanges priced at each rate. To see when each price took effect, run `akka optimize pricing-catalog versions list`. To read the prices at an instant, run `akka optimize pricing-catalog get --at` with that instant.

=== Compare two periods

[source,shell]
----
akka optimize spend compare --from 2026-09-15T16:00:00Z --to 2026-09-15T17:00:00Z \
  --against-from 2026-09-14T16:00:00Z --against-to 2026-09-14T17:00:00Z --by model
----

The answer gives the tokens and spend for each period, and the difference between them. A difference has a value only when both periods have one in the same currency.

=== Find the most expensive conversations

[source,shell]
----
akka optimize spend conversations list --from 2026-09-15T00:00:00Z --to 2026-09-16T00:00:00Z
----

This is a ranking of conversations by spend, not a division: the rows do not add up to the period total.
