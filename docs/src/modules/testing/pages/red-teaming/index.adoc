Red teaming is how a project probes a service for the things it should refuse.
A suite runs the target through attacker-shaped prompts drawn from a corpus, wraps or escalates them through attack styles, and asks a scorer whether the target broke through, held, or the evidence was inconclusive.
The rendered report lists each break as its own incident, grouped by hazard and by attack style, with a signed record the compliance review reads as evidence the run happened.

The pack is `evalkit-redteam`.
The customer-facing source root is `src/test/java/<groupId>.redteam/`, alongside the project's other tests.
The CLI is `akka redteam`.

== Shared with evaluation

Red teaming reads the same `SystemUnderTest` adapter an evaluation campaign uses.
A project already running evaluation reaches red teaming by adding the `evalkit-redteam` dependency and a new campaign class; the target adapter carries across unchanged.
`Rule`, `Scenario`, `Scorer`, `Campaign`, `Run`, `Rubric`, and `Ledger` mean the same thing in both packs.

== Techniques

A technique is how a payload is wrapped, escalated, or delivered before it reaches the target.
Every attack style implements the `Technique` interface and returns one or more prompts derived from an attacker goal.

Two families ship.

`Static` +
A pure function on a prompt.
The Base64 encoder, the role-play wrapper, the payload splitter across turns.
Reproducible across runs; the same goal produces the same prompt every time.

`Adaptive` +
An attacker with state.
Each next prompt reads the target's last reply and revises the attack.
Runs inside a durable driver so a mid-attack crash resumes from the same state.

For every technique the pack ships and the design of the driver, see xref:testing:red-teaming/techniques.adoc[] and xref:testing:red-teaming/adaptive-attacks.adoc[].

== Hazard taxonomies

Rules and scenarios carry hazard tags from two taxonomies.

*AILuminate v1.1* is the primary — twelve hazard categories the report groups by.
*OWASP LLM Top 10 (2025)* is the secondary — ten application-security risks a security review already knows.
Wire keys use the taxonomy prefix: `ailuminate:privacy`, `owasp:llm01_prompt_injection`.
For the full lists and how each scorer maps to them, see xref:testing:red-teaming/reference/hazards.adoc[].

== How red teaming relates to other components

* xref:testing:evaluation/index.adoc[Evaluation] measures the service under normal input.
Red teaming measures it under adversarial input.
Both read the same target adapter.
* xref:sdk:agents/guardrails.adoc[Guardrails] are the runtime component that refuses at request time.
Red-team scorers are the test-time component that finds the cases where a guardrail was bypassed.
* An xref:sdk:agents.adoc[Agent] is the service under test.
The adapter puts the Agent in front of the runner the same way an evaluation campaign does.
