= Custom evaluators
:page-summary: An Evaluator is a function over one case's reply and traced tool calls that returns a pass, a fail or an abstention; it runs per case through Expectations.satisfies or on every case through the runner.
:page-when-to-use: A check the built-in expectations do not cover and a judge should not decide, such as a rule over tool arguments or a limit on the reply.

A custom evaluator is a function over one case's evidence that reports a finding.

== The Evaluator interface

link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/Evaluator.html[Evaluator] has one method:

[source,java]
----
EvalResult evaluate(EvalCase evalCase, Interaction interaction, List<ToolCall> toolCalls);
----

The evaluator reads the case, the interaction and the tool calls.
It never calls the service.
It returns an `EvalResult` built with one of three factories.

[cols="1,3"]
|===
| Factory | Meaning

| `EvalResult.pass(name)`
| The check holds.

| `EvalResult.fail(name, detail)`
| The check does not hold. The detail is printed under the failed case.

| `EvalResult.abstain(name, detail)`
| The evidence the check needs is absent. Neither a pass nor a fail. The detail is printed in the report.
|===

The name is what the report prints and what `Gate.evaluatorRateAtLeast` refers to.
Choose one name per check and keep it stable.

== The evidence an evaluator reads

link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/Interaction.html[Interaction] is what one turn produced.

[cols="1,3"]
|===
| Accessor | Content

| `text()`
| The agent's reply, as the text the expectations read.

| `toolCalls()`
| The tool calls in call order. Each `ToolCall` has the name, the arguments as a map, the result and the error, both optional. The same list is passed as the third parameter.

| `modelCalls()`
| The model calls in call order, with the model name, the finish reasons, the token counts and the duration.

| `inputTokens()`, `outputTokens()`, `totalTokens()`
| Token counts summed over the model calls. Zero under a `TestModelProvider`.

| `guardrails()`
| Every guardrail evaluation, and `blocked()` when one blocked the turn.

| `latency()`
| From the start of the agent command to its end.

| `finalModelText()`
| The text of the last model response before the agent mapped it into the reply. Empty when the trace did not carry it.
|===

Tool arguments arrive as the runtime decoded them from the model's JSON, so a number is a `Number` and an object is a `Map`.

== An evaluator on every case

An evaluator given to the runner runs on every case of the experiment, in addition to each case's own expectations.
Use it for a rule that holds across the suite.

[source,java,indent=0]

----
include::sdk:example$doc-snippets/src/test/java/com/example/eval/OrderAgentQualityIntegrationTest.java[tag=run-level-evaluator]
----
<1> A lambda is an evaluator.
<2> Added to the experiment before the agent is named. Several `evaluator(...)` calls add several evaluators.
<3> The report rates the evaluator over the cases under its name, and a gate can refer to that name.
