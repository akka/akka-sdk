An experiment is a set of cases bound to an agent and a gate, run once for one report.

== Building an experiment step by step

link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/ExperimentRunner.html[ExperimentRunner] is created for the running TestKit.
It builds an experiment in a fixed order, and each step offers only what comes next, so an experiment without cases or without an agent does not compile.

[cols="1,1,3"]
|===
| Step | Returns | Methods

| `new ExperimentRunner(testKit)`
| `ExperimentRunner`
| `cases(first, more...)` or `cases(list)`. An empty list is rejected.

| `cases(...)`
| `ExperimentCases`
| `evaluator(evaluator)` adds an evaluator that runs on every case. `agent(...)` names the agent under test.

| `agent(...)`
| `Experiment`
| `gate(gate)` sets the gate. `run()` runs the cases and returns the report.
|===

Every method returns a new instance, so a partial experiment can be shared between tests.

<1> The gate. Without one, every case must pass.

The runner runs the cases one after the other in the calling thread.
Each case is called in a fresh session.
Nothing is persisted between runs.

[#naming-the-agent]
== Naming the agent

`agent(method)` takes the agent's command handler, for example `OrderAgent::ask`.
The handler takes the case's user message as a `String`.
A `String` reply is used as it is; any other reply type is rendered as JSON, and that JSON is the text the evaluators read.

`agent(method, command, replyText)` is for a handler with its own types.
`command` builds the command from the user message and `replyText` renders the reply as the text the evaluators read.

[#gates]
== Gates

A link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/Gate.html[Gate] is what the batch must satisfy over all case results.

[cols="2,3"]
|===
| Gate | Passes when

| `Gate.allCasesPass()`
| No case has a failed finding. This is the gate in force when none is given.

| `Gate.passRateAtLeast(rate)`
| The share of cases with no failed finding is at least the rate.

| `Gate.evaluatorRateAtLeast(evaluator, rate)`
| One evaluator's pass rate, over the cases where it did not abstain, is at least the rate. Fails when the evaluator judged no case. Evaluator names are in `Evaluators`, or the name a custom evaluator reports under.

| `Gate.noTargetFailures()`
| No case failed in its setup or in the agent call.

| `gate.and(other)`
| Both gates hold. The verdict lists both details.
|===

With a mocked model leave the gate out: the run is deterministic and every case must pass.
With a real model gate on rates, and add `noTargetFailures` so that an unavailable model or a broken stub fails the run for the right reason.

A failed gate does not throw.
Assert on the report, and use the rendered report as the failure message.

[#reading-the-report]
== Reading the report

`run()` returns an link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/ExperimentRunner.EvalReport.html[EvalReport].

[cols="1,3"]
|===
| Accessor | Content

| `passed()`
| Whether the gate passed.

| `passRate()`
| The share of cases with no failed finding.

| `cases()`
| One `CaseResult` per case, in the order the cases were given.

| `render()`
| The report as text.
|===

A rendered report of a passing batch:

[listing]
----
3/3 cases passed (100%)
gate: passed — pass rate 1.00 over 3 cases, required 0.90; tool-arguments rate 1.00 over 2 judged cases, required 1.00; no target failures
  tools 1/1
  tool-arguments 2/2
  forbidden-tools 2/2
  answer-contains 2/2
  tool-order 1/1
  answer-matches 1/1
  tool-call-budget 1/1
  model-call-budget 1/1
spend: 6 model calls, 0 tokens in, 0 out, 26 ms in total, slowest greeting at 10 ms, over 3/3 cases with evidence
----

Line by line:

. The cases with no failed finding, and the pass rate.
. The gate's verdict and its detail. A combined gate lists the detail of each part.
. One line per evaluator: the cases it passed over the cases it judged. An evaluator that abstained on some cases shows the count in brackets, for example `token-budget 0/0 (2 abstained)`.
. The spend: model calls, tokens and latency summed over the cases whose trace carried model calls, and the slowest case. The line is absent when no case carried model calls.
. After these lines, every failed case with its evidence, as described next.

== Reading a failed case

`CaseResult` carries the case id, the `Interaction` and the findings.
`passed()` is true when no finding failed.
`describe()` renders the evidence and the findings, and the rendered report includes it for every failed case.

----
0/1 cases passed (0%)
gate: FAILED — failed cases [wrong-order]
  tool-arguments 0/1
spend: 2 model calls, 0 tokens in, 0 out, 6 ms in total, slowest wrong-order at 6 ms, over 1/1 cases with evidence
case wrong-order FAILED
  reply: Order o_42 is shipped.

  model: 2 calls, 0 tokens in, 0 out, 6 ms

A failed case prints the reply, the tool calls with their arguments, the model spend, and every finding with its detail.
When the agent mapped the model's text into the reply, a `model text:` line shows the model's own text as well.
The reply is cut to one line of at most 200 characters.

== Setup and agent failures

A case whose setup throws is failed under the `setup` evaluator, and the agent is not called.
A case whose agent call throws is failed under the `target` evaluator.
The case keeps the tool calls the trace recorded before the failure, including the error the tool raised.

Neither failure aborts the batch.
`Gate.noTargetFailures()` turns them into a failed gate.

== Running a quality batch on demand

A batch against a real model costs money and time, and its result varies.
Keep it out of the regular build:

* Make the test class conditional. The sample uses JUnit's `@EnabledIfSystemProperty(named = "eval", matches = "true")`, so a plain `mvn verify` skips it. A JUnit `@Tag` with a Failsafe `groups` filter or a Maven profile serve the same purpose.
* Leave `withModelProvider` out of its TestKit settings, so the agent and the judge use the model configured in `application.conf`.
* Run it with the property set and the model's API key in the environment.

[source,bash]
----
mvn verify -Deval=true
----
