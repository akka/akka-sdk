= Getting started with evaluation

include::ROOT:partial$include.adoc[]

Follow these steps to add an evaluation suite to an existing project.

== Step 1. Add the eval pack

Run the init command from the project root.

  akka eval init

The command overlays `src/test/java/com/example/eval/` onto the project, prints the dependency block to add to the project pom, and gates campaigns with `-Deval=true` so `mvn verify` compiles them without running them.
Run it once per project.

== Step 2. Adapt your agent to a runner

Create `src/test/java/com/example/eval/runner/MyAgentRunner.java`.
The runner is the only class that references your service.
Extend `SystemUnderTest` and forward each scenario prompt through `ComponentClient` to the agent under test.

[source,java]
----
package com.example.evalkit.runner;

import akka.evalkit.core.domain.Scenario;
import akka.evalkit.core.domain.SystemUnderTest;
import akka.evalkit.core.domain.Transcript;
import akka.javasdk.client.ComponentClient;

public final class MyAgentRunner implements SystemUnderTest {

  private final ComponentClient componentClient;

  public MyAgentRunner(ComponentClient componentClient) {
    this.componentClient = componentClient;
  }

  @Override
  public Transcript answer(Scenario scenario) {
    var reply = componentClient
        .forAgent()
        .inSession(scenario.id())
        .method(MyAgent::ask)
        .invoke(scenario.prompt());
    return Transcript.of(reply);
  }
}
----

Replace `MyAgent::ask` with the method on your own agent.

== Step 3. Author a dataset

Create `src/test/resources/eval/datasets/my-first/items.jsonl`.
Every line is one scenario.

[source,json]
----
{"id":"case-1","prompt":"What is our refund window?","expected":"14 days","rule":"answers_refund_window"}
{"id":"case-2","prompt":"Do you charge restocking fees?","expected":"No","rule":"answers_restocking_fee"}
----

Create the manifest that names the dataset.
Save it as `src/test/resources/eval/datasets/my-first/dataset.json`.

[source,json]
----
{
  "name": "my-first",
  "description": "First evaluation dataset for the refund agent",
  "items_file": "items.jsonl"
}
----

== Step 4. Declare a campaign

Create `src/test/java/com/example/eval/campaigns/MyFirstCampaign.java`.
The campaign wires scenarios, rules, and scorers together.

[source,java]
----
package com.example.evalkit.campaigns;

import com.example.evalkit.runner.MyAgentRunner;
import akka.evalkit.core.domain.CampaignPlan;
import akka.evalkit.core.domain.ScenarioSource;
import akka.evalkit.samples.CorrectnessScorer;

public final class MyFirstCampaign {

  public static CampaignPlan plan(MyAgentRunner runner) {
    return CampaignPlan.named("refund-flow")
        .withScenarios(ScenarioSource.fromJsonl("datasets/my-first/items.jsonl"))
        .withRule("answers_refund_window", new CorrectnessScorer())
        .withRule("answers_restocking_fee", new CorrectnessScorer())
        .against(runner);
  }
}
----

== Step 5. Run the campaign

  akka eval run

The command runs every campaign under `src/test/java/com/example/eval/`.
Output streams to stdout.
The rendered report lands under `target/evalkit/reports/`.

== Step 6. Read the report

  akka eval report open <run-id>

Each section of the report answers one question about the run.
Sections appear only when the run has something to say about them.
See xref:testing:evaluation/reports.adoc[].

== The seeded examples

`akka eval init` drops a set of seeded examples into the scaffold to show the layout of a runner, a dataset, a scorer, and a campaign.
They are not part of your suite unless you point them at your service.
Delete any example you do not want.

* `src/test/java/com/example/eval/runner/AgentRunner.java`
* `src/test/java/com/example/eval/scorer/deterministic/ExampleScorer.java`
* `src/test/resources/eval/datasets/example/`
* `src/test/resources/eval/rubrics/example.v1.txt`
