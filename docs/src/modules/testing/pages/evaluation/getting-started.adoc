:page-prerequisites: An existing Maven project. Familiarity with JUnit.

This page walks from an empty project through the four things a first campaign needs: an adapter to the target, a dataset, a campaign class, and one run.

== Overview

A campaign is a JUnit test gated on `-Deval=true`.
`mvn verify` compiles it and leaves it out of the commit build; `mvn verify -Deval=true` runs it.
The eval tree lives under `src/test/java/<your-package>/eval/`, alongside the project's other tests.

== Add the eval pack

From the project root:

[listing]
----
akka eval init
----

The command overlays the eval tree onto the project's `src/test/java`, rewrites the scaffold's `com.example.eval` prefix to the target package (`<groupId>.eval` by default, or `--package` if set), and prints the dependency block to add to the pom.
It edits no pom itself.

Add the dependency block the command printed to the project's pom:

[source,xml,indent=0]
----
<dependency>
  <groupId>io.akka</groupId>
  <artifactId>evalkit</artifactId>
  <version>0.1.0-SNAPSHOT</version>
  <scope>test</scope>
</dependency>
----

== Adapt the target

Every campaign talks to one `SystemUnderTest`.
It puts the service into the state a scenario names, submits the graded turn, and returns what came back.
For an Akka SDK service, the adapter calls the service's own `ComponentClient`.

----
include::example$doc-snippets/src/test/java/com/example/eval/runner/AgentRunnerSample.java[tag=class]
----
<1> Inject the `ComponentClient` the same way a service's own tests do.
<2> `prepare(Precursor)` arranges the state the scenario needs.
A fixture named `"signed-in"` in the scenario reads the fixture handler here.
<3> A precursor this adapter cannot arrange returns `Prepared.Failed`, which the runner records as `NotReached` — a fact about the adapter, not a verdict on the target.
<4> `submit(sessionId, userText)` speaks the graded turn.
For an Agent, that is a `.forAgent().inSession(...).method(...).invoke(...)` call.
<5> `fixtures()` declares the states the adapter can reach.
A campaign that names a fixture this adapter never declared fails before running, rather than yielding a run of `NotReached` results.

== Write the campaign

The campaign class assembles the scenarios and the target, and calls `CampaignRunner.run(...)`.
Gate it on `-Deval=true` so `mvn verify` compiles it without running it.

----
include::example$doc-snippets/src/test/java/com/example/eval/campaign/FirstCampaignSample.java[tag=class]
----
<1> `@EnabledIfSystemProperty` gates the test on `-Deval=true`.
`mvn verify` alone compiles the class and skips execution.
<2> Every scenario names an id, a precursor, the graded turn, and the outcome the target is expected to reach.
<3> The plan collects the scenarios into a campaign, sets the number of parallel lanes, and names the rubric an agentic scorer would use.
<4> Construct the adapter written above.
<5> `CampaignRunner.run(...)` walks every scenario, calls the adapter, scores each run and returns a `CampaignResult`.
<6> The result carries the assertions.
`assertHeldAgainstBaseline` compares this run to a saved baseline and fails the test on regression.

For the assertions available on `CampaignResult`, see xref:testing:evaluation/campaigns.adoc[].

== Run it

Local:

[listing]
----
mvn verify -Deval=true
----

Every failing case appears in the JUnit output; the campaign's rendered report lands under `target/evalkit/reports/<campaign>.txt`.

To dispatch to the offline-evals service instead, see xref:testing:evaluation/remote-campaigns.adoc[].
