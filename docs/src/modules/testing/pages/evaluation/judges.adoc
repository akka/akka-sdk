A judge decides how well a reply meets a criterion stated as a sentence.

== What a judge decides

The built-in evaluators compare the reply and the tool calls against exact values.
Some criteria have no exact value.
A link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/Judge.html[Judge] scores such a criterion between 0 and 1, and the score becomes a result on the case under the `judge` evaluator.

A judged score can differ between runs of the same reply.
Gate a batch on the rate the judge passed rather than asserting on one judged case, see <<gating-a-judged-batch>>.

== Asking a model through the TestKit

`Judge.modelBased(testKit)` returns a link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/ModelBasedJudge.html[ModelBasedJudge] that asks a model through link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/JudgeAgent.html[JudgeAgent].
The verdict is one model call. It is not deterministic and consumes tokens.
`JudgeAgent` is an agent with the component id `eval-judge`.
The TestKit registers it when it starts; it is not part of the deployed service.

The judge asks the model configured in `akka.javasdk.agent.model-provider`, or the one named with `withModel`:

[source,java]
----
var judge = Judge.modelBased(testKit).withModel("eval.judge-model");
----

A model provider registered for `JudgeAgent.class` in the TestKit settings takes precedence over both. `TestKit.Settings.withModelProvider(JudgeAgent.class, provider)` accepts any `ModelProvider`, so it is another way to give the judge its own model.

Each verdict is decided in a new session with memory disabled, so one verdict does not influence the next.

[#stating-the-criterion]
== Stating the criterion

A criterion is one sentence that states what a good reply does, for example "the reply states only what the tools returned".
The judge scores the reply against it and returns the score with a one-sentence reason.

`mustSatisfy(criterion)` and `scoringAtLeast(criterion, threshold)` turn the judge into an `Evaluator`.

* `mustSatisfy` passes at a score of at least 0.5.
* `scoringAtLeast` passes at the given threshold.

The judge holds no criterion of its own, so one judge serves any number of them.
Each criterion gets one score and one reason.
A criterion that combines several properties, such as an apology, an amount and a length, still gets one score, and the reason does not say which property failed.
State one property per criterion, so that a failed result names the property that failed.

A criterion a program can decide, such as the length of the reply, belongs in a xref:testing:evaluation/eval-cases.adoc#custom-evaluators[custom evaluator], not in a judge.
`Judge` has one method, `decide(criterion, interaction)`, so a test can implement it as a lambda that returns a fixed `Verdict` to run judged cases without a model.

[#what-the-judge-sees]
== What the judge sees

The judge receives the criterion and the `Interaction`: the user message, the reply, and the tool calls with their arguments, results and errors.

`ModelBasedJudge` renders them as labeled sections and sends the text as the user message.
For the judged refund case in <<stating-the-criterion>> the default user message is:

[listing]
----
Criterion:
the reply apologizes and states the refunded amount

The user asked:
Order o_9 arrived broken. I want my money back.

The agent replied:
I am sorry the order arrived broken. I have refunded 49.99 to your card.

Tools called, in order:
- getOrder {orderId=o_9} -> {"id":"o_9","status":"delivered","totalCents":4999}
- issueRefund {orderId=o_9, amountCents=4999} -> {"orderId":"o_9","amountCents":4999,"reference":"ref_1"}
----

A tool call that failed shows `-> failed:` and the error instead of a result.
A case that called no tool has no `Tools called` section.

The system message is `ModelBasedJudge.DEFAULT_SYSTEM_MESSAGE`:

[source,java,indent=0]
----

----

The judge appends `ModelBasedJudge.REPLY_FORMAT` to the system message, which asks for the reply as a JSON object with a `score` between 0 and 1 and a `reason`.

`withSystemMessage(text)` returns a judge with another system message. The reply format is appended to that message too, so a custom message does not need to ask for it.
`systemMessage()` returns the system message a judge sends, with the reply format appended.

`withUserMessage(function)` returns a judge that renders the criterion and the `Interaction` into the user message with the given function, for example to label the sections in the language of the cases.

`ModelBasedJudge.defaultUserMessage(criterion, interaction)` is the default rendering in <<what-the-judge-sees>>. A custom rendering must carry what the system message asks the model to judge.

== When the judge is inconclusive

The `judge` evaluator is inconclusive, and the case is not failed, when:

* the reply is empty or blank, so there is nothing to judge;
* the judge throws, for example because the model is unavailable;
* the score is not between 0 and 1.

The inconclusive result carries the reason and appears in the report as `INCONCLUSIVE akka-eval:judge:` followed by the criterion and the reason.
xref:testing:evaluation/eval-cases.adoc#inconclusive[Inconclusive results] describes how the report and the gates count inconclusive results.

[#gating-a-judged-batch]
== Gating a judged batch

With a real model, hold a batch to the rate the judge passed.
`Gate.evaluatorRateAtLeast(Evaluators.JUDGE, rate)` rates the `judge` evaluator over the cases where it was conclusive, and fails when it judged no case.
