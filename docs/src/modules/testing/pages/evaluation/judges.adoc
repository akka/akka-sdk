A judge is a model that scores a reply against a criterion written in words.

== What a judge decides

The built-in evaluators compare the reply and the tool calls against exact values.
Some criteria have no exact value.
A link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/Judge.html[Judge] scores such a criterion between 0 and 1, and the score becomes a finding on the case under the `judge` evaluator.

A judged score can differ between runs of the same reply.
Gate a batch on the rate the judge passed rather than asserting on one judged case, see <<gating-a-judged-batch>>.

== Asking a model through the TestKit

`Judge.agent(testKit)` returns an link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/AgentJudge.html[AgentJudge] that asks a model through link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/JudgeAgent.html[JudgeAgent].
`JudgeAgent` is an agent with the component id `eval-judge`.
The TestKit registers it when it starts; it is not part of the deployed service.

Unless the TestKit settings register a model provider for `JudgeAgent.class`, the judge asks the model configured in `akka.javasdk.agent.model-provider`.

To mock the judge, register a `TestModelProvider` with `TestKit.Settings.withModelProvider(JudgeAgent.class, provider)`, as for any other agent.
The mocked reply must be the JSON object the judge reads: `{"score": 1.0, "reason": "mocked"}`.

Each judge question runs in a new session with memory disabled, so one judgement does not influence the next.

== Stating the criterion

A criterion is one sentence that states what a good reply does, for example "the reply states only what the tools returned".
The judge scores the reply against it and returns the score with a one-sentence reason.

`mustSatisfy(criterion)` and `scoringAtLeast(criterion, threshold)` turn the judge into an `Evaluator`, given to a case next to the built-in evaluators.

* `mustSatisfy` passes at a score of at least 0.5.
* `scoringAtLeast` passes at the given threshold.

The judge holds no criterion of its own, so one judge serves any number of them.
Each criterion gets one score and one reason.
A criterion that combines several properties, such as an apology, an amount and a length, still gets one score, and the reason does not say which property failed.
State one property per criterion, so that a failed finding points at the property that failed.

A criterion a program can decide, such as the length of the reply, belongs in a xref:testing:evaluation/eval-cases.adoc#custom-evaluators[custom evaluator], not in a judge.
`Judge` is a functional interface, so a test can return a fixed `Verdict` to run judged cases without a model.

== What the judge sees

The judge receives a `Judge.Question`: the criterion, the user message, the reply, and the tool calls with their arguments, results and errors.

`AgentJudge` renders the question as labelled sections and sends it as the user message.
For the judged refund case above the user message is:

[listing]
----
Criterion:
the reply apologises and states the refunded amount

The user asked:
Order o_9 arrived broken. I want my money back.

The agent replied:
I am sorry the order arrived broken. I have refunded 49.99 to your card.

Tools called, in order:
- getOrder {orderId=o_9} -> {"id":"o_9","status":"delivered","totalCents":4999}
- issueRefund {orderId=o_9, amountCents=4999} -> {"orderId":"o_9","amountCents":4999,"reference":"ref_1"}
----

A tool call that failed shows `-> failed:` and the error instead of a result.
A case that called no tool has no `Tools called` section.

The system message is the prompt below, read from `eval/judge-prompt.txt` on the classpath.

[listing]
----
You judge whether an agent's reply meets a stated criterion.

You will be given the criterion, the message the user sent, the reply the agent produced,
and the tools it called to produce that reply. Score how fully the reply meets the
criterion, between 0 (does not meet it) and 1 (fully meets it). Judge the criterion you
were given and nothing else: a reply you would have worded differently still meets a
criterion it satisfies.

Reply as JSON: {"score": <number between 0 and 1>, "reason": "<one sentence>"}
----

`withPrompt(prompt)` returns a judge with another system message; `prompt()` returns the system message a judge sends.
A custom prompt must ask for the same reply format: a JSON object with a `score` between 0 and 1 and a `reason`.

== When the judge abstains

The `judge` evaluator abstains, and the case is not failed, when:

* the reply is empty or blank, so there is nothing to judge;
* the judge throws, for example because the model is unavailable;
* the score is not between 0 and 1.

The abstention carries the reason and appears in the report as `ABSTAIN judge:` followed by the criterion and the reason.
xref:testing:evaluation/eval-cases.adoc#abstaining[Abstaining when the evidence is absent] describes how the report and the gates count abstentions.

[#gating-a-judged-batch]
== Gating a judged batch

With a real model, hold a batch to the rate the judge passed.
`Gate.evaluatorRateAtLeast(Evaluators.JUDGE, rate)` rates the `judge` evaluator over the cases where it did not abstain, and fails when it judged no case.
