An eval case is one turn with the agent and the evaluators its reply and tool calls must pass.

== The parts of an eval case

link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/EvalCase.html[EvalCase] is a record with four parts.

[cols="1,3"]
|===
| Part | Meaning

| `id`
| Names the case in the report. Unique within the suite.

| `userMessage`
| The message the agent receives. The runner turns it into the command with the mapping given to `agent(...)`, see xref:testing:evaluation/experiments.adoc#naming-the-agent[Naming the agent].

| `setup`
| A `Runnable` that runs before the agent is called. Use it to prime the stubs the agent's tools call, or to seed entities through the component client. `EvalCase.NO_SETUP` when the case needs none. `EvalCase.of(id, userMessage, evaluators...)` creates a case without a setup.

| `evaluators`
| The checks the turn must pass, as a list or as trailing arguments. Empty when the case only collects evidence. `withEvaluators(...)` returns the same case with more evaluators.
|===

A case that throws in its setup is reported as failed under the `setup` evaluator.
The agent is not called.

Each case runs in a fresh session, so no case can read the session memory of an earlier case.

== Evaluators

An link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/Evaluator.html[Evaluator] is one check over the reply and the traced tool calls of a turn.
It reports a finding: pass, fail, or abstain when the evidence it needs is absent.
A case carries any number of evaluators, and they are all of the same type:

* the built-in evaluators, created through the factories in link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/Evaluators.html[Evaluators];
* a criterion scored by a model, created through a xref:testing:evaluation/judges.adoc[Judge];
* a <<custom-evaluators,custom evaluator>> of your own.

An evaluator given to `experimentRunner.cases(...).evaluator(...)` runs on every case of the experiment instead of one.

=== Built-in evaluators on tool calls

[cols="1,2,3"]
|===
| Evaluator | Created with | Passes when

| `tools`
| `Evaluators.tools(names...)`
| Every named tool was called, in any order. Other calls are allowed.

| `tool-order`
| `Evaluators.toolOrder(names...)`
| The named tools were called in this relative order. Calls to other tools may come between. Abstains when one of the named tools was never called.

| `tool-arguments`
| `Evaluators.toolArgument(tool, argument, value)`
| A call to the tool carried the argument with this value. Abstains when the tool was never called.

| `tool-results`
| `Evaluators.toolResult(tool, needle)`
| The result of the tool contains the text, case-insensitively. Abstains when the tool was never called or the trace carries no result for it.

| `forbidden-tools`
| `Evaluators.forbiddenTools(names...)`
| None of the named tools was called.
|===

=== Built-in evaluators on the reply

[cols="1,2,3"]
|===
| Evaluator | Created with | Passes when

| `answer-contains`
| `Evaluators.answerContains(needles...)`
| The reply contains every needle, case-insensitively.

| `answer-matches`
| `Evaluators.answerMatches(regex)`
| The reply matches the regular expression anywhere. Anchor the expression for a full match. A pattern that does not compile fails the case.
|===

=== Built-in budgets

[cols="1,2,3"]
|===
| Evaluator | Created with | Passes when

| `tool-call-budget`
| `Evaluators.toolCallsAtMost(calls)`
| The agent made at most this many tool calls.

| `model-call-budget`
| `Evaluators.modelCallsAtMost(calls)`
| The agent made at most this many model calls. An answer takes at least one.

| `token-budget`
| `Evaluators.tokensAtMost(tokens)`
| Input and output tokens together stay within the limit. Abstains when the model reported no tokens.

| `latency-budget`
| `Evaluators.latencyAtMost(duration)`
| The agent command completed within the duration. Abstains when the trace carries no timing.
|===

== Custom evaluators

A custom evaluator implements link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/Evaluator.html[Evaluator]: `name()` returns the name its findings are reported under, and `evaluate(...)` receives the case and everything the runtime traced for the turn and returns a `Finding`: a pass, a fail with a reason, or an abstention.

== Abstaining when the evidence is absent

An evaluator reads only what it names and abstains when that evidence is absent.
A tool that was never called fails `tools` and makes `tool-order` and `tool-arguments` abstain, so one missing call is reported once.
An abstention is neither a pass nor a fail.
A case with abstentions and no failed finding passes.
The report counts abstentions per evaluator name, and `Gate.evaluatorRateAtLeast` rates evaluators over the findings that did not abstain.
