= Scorers

include::ROOT:partial$include.adoc[]

A scorer turns a recorded run into a verdict for one rule.
Every scorer implements `akka.evalkit.core.domain.Scorer` — the interface every family flows through — and returns a `RunOutcome` that tells the campaign what to do next.

evalkit ships 22 scorers in three families: 3 deterministic, 12 heuristic, 7 agentic.
The customer picks which to run, wires the agentic ones with a model, and adds their own for anything specific to the domain.

== The three families

*Deterministic* — comparison against an expectation.
Zero model calls, zero interpretation.
A tool call that was on the allow list; a reply that contains a required substring; a tool argument that matched the expected map.
Two runs on the same recorded interaction decide identically.

*Heuristic* — computation over the recorded interaction.
Zero model calls, but a rule of thumb rather than a comparison.
A budget the latency has to stay under; a regex the reply has to match; a JSON payload that has to parse; overlap between the reply and the expected outcome.

*Agentic* — a language model reads the exchange and returns a verdict.
Non-zero cost per run, non-deterministic (two runs on the same interaction may disagree at the edges), and the only honest answer for questions like _"is this claim supported by the retrieved passages?"_ where every heuristic misclassifies negation and paraphrase.

The three families cascade in cost: deterministic first (free, certain), heuristic second (cheap, ~70% accurate on clear cases), agentic last (expensive, gold standard on the borderline).

== The interface

Every scorer, in every family:

[source,java,indent=0]
----
public interface Scorer {
  RunOutcome score(Observation observation);
  default String id() { return getClass().getSimpleName(); }
}
----

`RunOutcome` is one of six results: `Asserted` (a pass or fail from comparison), `Measured` (a number against a threshold), `Scored` (a graded band from a rubric), `Inconclusive` (the scorer had nothing to read), `NotReached` (the run never happened), `Failed` (the scorer itself broke).
A scorer that could not settle a case returns `Inconclusive` — never a made-up number.

== The built-in scorers

The tables below name every scorer evalkit ships out of the box and what each reads.
The reference table under xref:reference:cli/akka-cli/akka_eval.adoc[] carries the full input, verdict and configuration details.

=== Deterministic (3)

[cols="1,3"]
|===
| Scorer | What it reads

| `ToolPermission`
| Tool names against an allow list, a deny list, or both. A deny outranks an allow on conflict.

| `ToolCorrectness`
| Tool names against a stated expected list. Order-sensitive when configured.

| `ArgumentCorrectness`
| Tool argument maps against expected maps. Parses each tool call's JSON arguments.
|===

=== Heuristic (12)

Budget scorers read fields directly off the recorded interaction:

[cols="1,3"]
|===
| Scorer | What it reads

| `LatencyBudget`
| `Interaction.latency()` against a stated `Duration`. Half at budget, proportional above it.

| `TokenBudget`
| Total input+output tokens against a limit. A run with no measured usage is `Inconclusive`.

| `ModelCallBudget`
| `Interaction.modelCalls().size()` against a limit.
|===

Format scorers read the response text:

[cols="1,3"]
|===
| Scorer | What it reads

| `RegexMatch`
| Reply against a compiled `Pattern`. `matching(regex)` or `notMatching(regex)`.

| `LengthInRange`
| Reply length against `[min, max]`. `characters(min, max)` or `words(min, max)`.

| `JsonValidity`
| Whether the reply parses cleanly as JSON, trailing garbage included in the failure.
|===

Text-overlap scorers compare against `scenario.expectedOutcome()`:

[cols="1,3"]
|===
| Scorer | What it reads

| `ExactMatch`
| Reply against the expected outcome, whitespace-normalised. Case-sensitive by default; `ignoringCase()` for QA.

| `TokenF1`
| SQuAD-style token overlap F1. Passes the paraphrases exact-match rejects.
|===

Retrieval-quality scorers read `Interaction.retrievedContext()` against a customer-supplied ground-truth lookup:

[cols="1,3"]
|===
| Scorer | What it reads

| `ContextRecall`
| Share of relevant passages that retrieval returned. Ground truth is a `Function<Observation, List<String>>`.

| `ContextPrecision`
| Share of retrieved passages that were labelled relevant.

| `ReciprocalRank`
| 1 / rank of the first relevant passage in retrieval's output.

| `NormalizedDiscountedCumulativeGain`
| NDCG@K over the retrieved passages. Binary relevance in the first version; graded relevance is a later extension.
|===

Matching is exact-string equality after trimming.
A customer whose passages need fuzzy matching wraps their own scorer that pre-processes both sides.

=== Agentic (7)

Every agentic scorer extends `AlignmentMetric` and takes an `Assessor` in its constructor.
Every one also ships a `systemPrompt()` — the wording is evalkit's problem, the model call is the customer's.

[cols="1,3"]
|===
| Scorer | What the model judges

| `TaskCompletion`
| Whether the reply carried out the task the scenario stated.

| `PlanQuality`
| Whether the plan the agent formed would achieve the task.

| `PlanAdherence`
| Whether the agent followed the plan it formed.

| `StepEfficiency`
| Whether the sequence of model calls and tool calls was efficient for the task.

| `TurnFaithfulness`
| Whether the reply is supported by the passages retrieval returned.

| `TurnRelevancy`
| Whether the reply addresses the question that was asked.

| `CitationFaithfulness`
| Whether each citation marker in the reply points at a passage that supports the claim beside it.
|===

== Wiring an agentic scorer

The customer supplies the model.
The scorer ships the system prompt and enforces the JSON verdict shape.

[source,java,indent=0]
----
import akka.evalkit.core.metric.AlignmentMetric;
import akka.evalkit.core.metric.TurnFaithfulness;

var faithfulnessAssessor = (AlignmentMetric.Assessor) question ->
    judgeAgent.query(question.task() + "\n\n---\n\n" + question.against())
              .systemMessage(new TurnFaithfulness(null).systemPrompt())
              .responseConformsTo(AlignmentMetric.Assessment.class)
              .invoke();

var faithfulness = new TurnFaithfulness(faithfulnessAssessor);
----

`Assessment` is a two-field record: `score` in `[0, 1]` and `reason` as one sentence.
The Akka SDK's `.responseConformsTo(Assessment.class)` enforces the JSON shape at the SDK layer — a model that returns something malformed is retried before the assessor sees it.

There is no default agent-backed judge shipped in evalkit.
The choice of model, provider and cost is the customer's, and the assessor function is what keeps it that way.

== Writing your own scorer

Custom scorers land under `src/test/java/<your-package>/eval/scorer/{deterministic,heuristic,agentic}/`.
See the module's `AUTHORING.md` (also linked from the scaffold README) for the walkthrough of one shipped scorer per family and templates you can copy.

A deterministic example — a scenario naming a required substring:

[source,java,indent=0]
----
public final class RefundWindowScorer implements Scorer {
  private static final MetricRef REF = new MetricRef("refund_window_named", 1);

  @Override public String id() { return REF.label(); }

  @Override
  public RunOutcome score(Observation observation) {
    String reply = observation.interaction().responseText();
    if (reply == null || reply.isBlank()) {
      return new RunOutcome.Inconclusive("no reply");
    }
    boolean stated = reply.matches("(?i).*\\b30[- ]day\\b.*");
    return new RunOutcome.Asserted(stated, "30-day refund window",
        stated ? "found in the reply" : "not stated in the reply");
  }
}
----

An agentic example — extend `AlignmentMetric`, wire an assessor per the pattern above:

[source,java,indent=0]
----
public final class Politeness extends AlignmentMetric {
  public Politeness(Assessor assessor) {
    super(new MetricRef("politeness", 1), 0.7, assessor);
  }

  @Override
  protected Optional<Question> ask(Observation observation) {
    String reply = observation.transcript().systemOutput();
    return reply.isBlank() ? Optional.empty()
      : Optional.of(new Question("reply", "a customer-service reply", reply));
  }

  @Override protected String absence() { return "no reply to judge for politeness"; }

  @Override
  public String systemPrompt() {
    return """
      You judge how polite a reply is on a scale of 0 (rude) to 1 (courteous).
      Reply as JSON: {"score": <number in [0,1]>, "reason": "<one sentence>"}.
      """;
  }
}
----

Add the class to `AlignmentMetric`'s `permits` clause if you want it to be picked up by the classpath coverage check, or use `non-sealed` in your own intermediate class for an open hierarchy.

== Best practices

* Prefer the earliest family that answers the rule.
A deterministic check that catches the same failures as an agentic judge costs zero and never disagrees with itself.
* Return `Inconclusive` when there is nothing to read.
A scorer that scored an empty reply as failed reports a defect the target never had a chance to make.
* Change the metric's version when a setting change would silently redefine what a recorded score means — the threshold, the allow list contents, a system prompt's wording.
Not for a rename that doesn't touch scoring.
* Ship a system prompt with every agentic scorer.
The wording is part of the metric's identity; the customer picks the model, but the prompt travels with the version.
