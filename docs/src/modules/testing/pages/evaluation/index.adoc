= Evaluation
:page-summary: An evaluation suite runs a service against a set of scenarios and records a verdict for each. Reports carry pass rates, the cases that failed, and the cost of the run — enough for a CI job to gate a merge on regression.
:page-when-to-use: Use when a service is worth measuring. The reply's correctness, the tool usage, the latency budget, the faithfulness of a retrieved answer.

Evaluation is how a project measures a service against a stated expectation.
A suite runs the service through a fixed set of scenarios and turns each reply into a verdict.
The rendered report lists the failing cases one by one, and the CI job fails the build when the pass rate drops or a case that used to pass now fails.

== The parts of a campaign

`Scenario` +
A graded turn, what a correct answer does, an optional specification node or metric, and an
optional precursor that seeds the conversation first.
Scenarios are Java records; evalkit ships no reader for an on-disk format.

`Scorer` +
One method that turns a recorded run into an outcome.
Three families ship: deterministic (comparison against a stated expectation), heuristic
(computation from the recorded interaction against a threshold), and agentic (a
language-model judge configured with a shipped system prompt).
See xref:testing:evaluation/scorers.adoc[].

`Requirement` +
One scenario together with every run of it.
Repeating a campaign produces several runs and one requirement, and the report reads
requirements so a scenario that passes twice and fails once is one varied requirement.

`Campaign` +
The JUnit class that assembles the scenarios, the target and the scorers into a named unit
and runs them.
Gated on `-Deval=true` so `mvn verify` compiles the class without running it.

`Run` +
One execution of a campaign against one target build.

`Report` +
The output of a run.
See xref:testing:evaluation/reports.adoc[] for every panel and how the numbers compose.

== How evaluation relates to other components

* xref:testing:red-teaming/index.adoc[Red teaming] runs the same target through adversarial prompts and reports each break as an incident.
Red-team scorers use the same three-family taxonomy the evaluation scorers use.
* An xref:sdk:agents.adoc[Agent] is the service being evaluated.
A test adapter — `SystemUnderTest` — puts the Agent in front of the runner.
