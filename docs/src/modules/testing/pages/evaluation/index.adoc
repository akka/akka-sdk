Evaluation runs an agent through a set of eval cases and checks each reply, and the tool calls behind it, against stated expectations.

== Overview

evalkit is the evaluation part of the Akka TestKit: the `akka.javasdk.testkit.eval` package in the `akka-javasdk-testkit` artifact.
An evaluation is a JUnit test that extends `TestKitSupport`.
The agent runs in the in-process runtime with its tools, session memory and guardrails.
The runtime traces every model call and tool call, and the evaluation reads that trace as evidence.
Nothing is persisted and nothing leaves the test JVM.

Use evaluation for three purposes.

Wiring, in every build::
Mock the model with `TestModelProvider` and assert that the agent calls the right tools with the right arguments, and turns the tool results into the reply.
Every case must pass.

Quality, on demand::
Run the same cases against a real model.
Replies vary between runs, so a gate holds the batch to a pass rate rather than every case to a pass.
A model judge scores criteria that the built-in expectations cannot state, such as tone.

Baseline, from recordings::
Turn recorded production interactions into cases with `EvalCaseParser`.
A replayed case expects the tools, the order and the arguments production used, and holds the agent to the recorded spend.

Evaluation is not the place for the following.

* The effect one command produces. Use xref:testing:unit.adoc[] and the agent's `TestKit`.
* An endpoint's HTTP contract, or the wiring between components without an agent. Use xref:testing:integration.adoc[].

== How a case runs

`ExperimentRunner` runs the cases one after the other, in the calling thread.

. The case's setup runs. It primes the stubs the agent's tools call.
. The runner calls the agent's command handler through the TestKit component client, in a fresh session, with the case's user message.
. The runner reads the trace the runtime wrote for that session through `TelemetryReader`: the tool calls with their arguments, results and errors, the model calls with their token counts, the guardrail evaluations and the latency.
. Every evaluator the case activated reads the reply and the trace and reports a finding: pass, fail, or abstain when the evidence it needs is absent.
. The gate checks the aggregated results and the report is returned.

[mermaid]
----
flowchart LR
    Case[EvalCase] --> Runner[ExperimentRunner]
    Runner -->|command, fresh session| Agent[Agent in the TestKit runtime]
    Agent -->|reply| Runner
    Agent -.->|trace| Telemetry[TelemetryReader]
    Telemetry --> Runner
    Runner --> Evaluators[Built-in evaluators, judges, custom evaluators]
    Evaluators --> Findings[Findings per case]
    Findings --> Gate
    Gate --> Report[EvalReport]
----

A case that fails in its setup, or whose agent call throws, is reported as a failed case under the `setup` or `target` evaluator.
It does not abort the batch.

== The parts of an evaluation

[cols="1,3"]
|===
| Type | Role

| `EvalCase`
| One case: an id, the user message, a setup that runs before the call, and the expectations. See xref:testing:evaluation/eval-cases.adoc[].

| `Expectations`
| What the case asserts. Each declaration activates one built-in evaluator. See xref:testing:evaluation/eval-cases.adoc[].

| `Judge`
| A model that scores the reply against a criterion written in words. See xref:testing:evaluation/judges.adoc[].

| `Evaluator`
| A custom check over the reply and the tool calls. See xref:testing:evaluation/custom-evaluators.adoc[].

| `ExperimentRunner`
| Builds the experiment step by step: the cases, the agent, the gate, then the run. See xref:testing:evaluation/experiments.adoc[].

| `Gate`
| What the batch must satisfy over all case results. Without a gate every case must pass. See xref:testing:evaluation/experiments.adoc[].

| `EvalReport`
| The outcome: whether the gate passed, the pass rate, every case result, and the report as text. See xref:testing:evaluation/experiments.adoc[].

| `EvalCaseParser`, `ToolBindings`
| Cases derived from recorded interactions. See xref:testing:evaluation/replay.adoc[].
|===

All types are in the `akka.javasdk.testkit.eval` package.
The API documentation is at link:{attachmentsdir}/testkit/akka/javasdk/testkit/eval/package-summary.html[akka.javasdk.testkit.eval].
